# 실제 게임 자료 영상 제작 방침

## 처음 보는 사람의 이해도와 참고 게임 선택 — 2026-10-10 추가 지시

참고 마사히로 영상에 나온 게임도 후보로 사용할 수 있다. 같은 게임을 쓴다는 이유만으로 채택하지 않고, 사용할 실제 원본의 권리와 정확한 행동을 확인한다. 다른 게임이 질문·동작·결과를 더 분명하게 설명하면 비교 근거를 기록해 그 게임을 고른다. 게임을 처음 보는 사람이 규칙·대상·전후 변화를 따라갈 수 있는지 정상 속도로 비교하고 필요한 UI/조작 안내를 대본 앞에 배치한다. ‘유명한 게임’, ‘새 게임’, ‘확보된 긴 영상’은 이해도 검수를 대체하지 않는다.

후보별 시작 상태, 행동, 보이는 결과, 시점/가림/UI, 필요한 사전 설명, 선정/제외 이유와 참고 영상에 연결되는 질문을 기록한다. 수학 표시의 대상과 역할별 색을 이 관찰에 맞춰 계획하고 움직이는 최종 영상에서 다시 확인한다. 이번 최신 요청은 아직 게시되지 않은 예약/비공개 제작물에도 적용한다. 공개 완료본과 사용하지 않는 역사 원본은 보존하며 현재 Studio 상태와 전용 수정 큐로 대상을 확인한다.

## 이해가 잘되는 실제 장면 비교와 화면 위 수학 해설 — 2026-10-10 승인

사용자 요청: `실제 게임영상 비교해서 찾을때 좀더 잘 이해되는 영상인지 꼭 확인해서 골라줘`, `영상위에 실제 우리가 다루는 수학내용을 빨간선이나 다양한 색의 도형을 넣어서 그위에 같이 그려서 설명 ... 이것도 영상규칙에 추가해줘`.

**선정 전에 실제 구간을 재생해 비교한다.** 같은 개념의 후보에서 시작 상태 → 관련 행동 → 결과가 분명하게 보이는지 확인하고, 처음 보는 시청자가 내레이션과 표시를 통해 그 차이를 이해하기 쉬운 장면을 선택한다. 게임의 유명세·새로움, 검색 제목, 보유 파일 여부만으로 선정하지 않는다. 좌표·회전·보간을 설명하려면 회전축과 기준 방향, 대상 물체, 카메라 시점이 파악되고 변화의 전후가 보이는 구간을 우선한다. 빠른 편집·흔들림·가림·효과·UI 때문에 핵심 변화가 읽히지 않는 구간은 다른 후보보다 이해가 어려운 이유를 기록하고 제외하거나 필요한 별도 설명 컷을 계획한다.

`sources/game-candidates.json` 또는 기존 출처 기록에 비교한 게임/원본URL/정확한 구간, 설명할 주장, 보이는 전후 변화, 시점·가림·UI·동작의 명료성, 선정/제외 이유를 남긴다. 실제로 재생하지 않은 후보를 검토 완료로 기록하지 않는다. 후보가 부족하면 그 사실과 확인한 범위를 남기고 자료를 더 확보한다. 선택한 구간의 화면을 먼저 확인한 다음 보이는 행동에 맞춰 대본과 수학 표시를 작성한다.

**선택한 게임 화면 위에서 수학을 함께 설명한다.** 회전축·현재/목표 방향 화살표·회전각 호·이동 궤적·거리선·충돌 원/영역·평면 등 해당 주제를 이해시키는 표시를 직접 그린다. 핵심 대상에는 빨간선, 비교 대상과 서로 다른 역할에는 구별되는 색의 선·도형을 사용하고, 무엇을 뜻하는지 짧은 라벨과 해설로 연결한다. 회전을 설명한다면 ‘캐릭터의 회전 중심/축 표시 → 현재 방향과 목표 방향 비교 → 회전각 표시 → 실제 돌아가는 결과’처럼 내레이션과 함께 단계적으로 보여 준다. 모든 장면에 같은 원과 화살표를 장식처럼 붙이지 않는다.

표시는 실제 대상과 카메라 움직임에 맞게 따라가야 하며 중요한 게임 동작·UI·고정 하단 자막을 가리지 않는다. 실제 재생과 시작/중간/끝·카메라 전환에서 위치·각도·색·가독성을 검수한다. 수학적으로도 화면에 투영된 2D 각도/거리와 게임 월드의 3D 값은 구분한다. 확인하지 않은 내부 구현·속도·좌표·회전각을 게임의 실제 값으로 단정하지 않고, 필요하면 ‘설명용 예시’라고 표시한다. 상세 화면 기준은 [디자인 기준](VIDEO_VISUAL_STYLE.md)의 게임 화면 위 수학 표시 항목을 따른다.

원본 게임 파일과 편집 가능한 표시 레이어를 보존한다. 실제 동작을 관찰하는 화면 위의 보조 선·도형은 실제 영상 시간이며 설명 시간에 중복 계산하지 않는다. 분석을 위한 정지 프레임이나 도식·계산이 중심이 된 구간은 설명 시간으로 분류한다. 새 제작과 미완료 제작에 적용하며, 기본 실제60%/설명40%와 사용자가 승인한 강의 실제40%/설명60% 등 프로젝트별 비중·무음악 예외는 그대로 따른다.

2026-10-02 사용자 지시: `게임 시나리오 쓰는 법 영상도 실제 게임영상을 가져와서 만들어야지 너가 직접 만드는개 아니야 앞으로는그렇개 해줘 그리고 제작방침에 기록해줘`.

## 적용 원칙

- 새 영상과 아직 완료하지 않은 영상의 게임 예시는 **실제로 존재하는 게임의 실제 플레이 자료 영상**을 확보해 사용한다. 공식 게임플레이·개발사의 실제 플레이 시연·사용 조건을 확인한 플레이 녹화에서 개념에 맞는 장면을 선정한다. 출시 전 공식 자료는 개발 당시 버전도 기록한다.
- 예시를 채우려고 에이전트가 게임·프로토타입·이야기 데모·경주·시뮬레이터를 새로 만들거나 렌더하지 않는다. 직접 만든 데모는 실행 가능해도 실제 게임 자료의 대체물이 아니며 60%에 넣지 않는다. 사용자가 별도로 제작을 요청한 경우만 그 요청 범위에서 다룬다.
- **본편 실제 게임 자료 영상60% / 흰2.5D 설명40%**를 유지한다. 인트로2초와 회원 엔딩10초는 제외하고 최대1프레임 반올림만 허용한다. 설명용 도식·비교·화살표·강조 애니메이션은 계속 직접 제작한다. 사용자가 명시적으로 요청한 프로그래밍 실습/실제 개발 시연은 그 요청을 따르되, 게임 예시를 임의의 데모로 대체할 근거로 확대하지 않는다.
- 좋은 PPT의 주장·설명은 보존하고, 해당 개념이 실제로 드러나는 게임 장면과 해설을 주요 설명 사이에 삽입한다. 필요하면 대본과 전체 길이를 늘린다.

## 자료 확보 → 해설 → 제작

1. 기존 제작물과 현재 채널의 내용 중복을 검토한다.
2. 주제에 맞는 실제 게임 후보와 최근 사용 이력을 새로 확인한다. 기존 파일을 자동 재사용하지 않는다.
3. 자료를 직접 보고 게임명·업로더·원본URL·버전·사용 조건·정확한 인아웃·보이는 행동·관찰 지점·연결할 PPT 주장을 `sources/game-candidates.json`과 컷 계획에 기록한다.
4. 충분한 실제 장면을 확보한 뒤 **화면에서 확인되는 행동에 맞춰** 한영 해설과 TTS를 작성한다. 가상 상황을 먼저 대본에 쓰고 그에 맞는 게임을 직접 만들어 끼워 넣지 않는다.
5. 자료가 부족하면 다른 실제 게임/구간을 찾는다. 자체 데모·루프·저속·무관한 대기·시네마틱·메뉴/점수표로 실제 플레이 분량을 채우지 않는다.
6. 컷별 출처와 행동이 대사에 맞는지 검수한다. 게임은 전체 화면으로 보여주고 모든 내레이션의 한글 박스 자막을 아래 가운데에 고정한다. 내부 출처·권리 기록도 유지한다.

## 진행 중 작업과 과거 기록

- **picking-sides부터 즉시 적용**한다. 자체 구름섬 우편 경주(Cloudpost) 테이크와 이에 의존한 예시 대사는 최종 계획에서 제외하고 실제 게임 자료로 재계획한다. 원본 파일·제작 이력은 삭제하지 않는다. 기존 여섯 PPT의 주장·설명은 유지하며 실제 예시 연결 문장은 새 자료와 대조한다.
- `game-writing`의 자체 이야기 게임 사용은 이번 변경의 계기가 된 과거 이력이다. 과거 영수증을 새 기준에 적합하다고 다시 표기하지 않는다. ‘앞으로는’ 지시만으로 기존 완료 영상을 자동 재제작·삭제·재업로드하거나 공개 상태를 변경하지 않는다.
- 이 지침은 이전의 ‘의미 있는 자체 플레이테스트도 실제 영상으로 계산’ 규칙보다 우선한다. 과거 완료 기록은 보존하고 신규·진행 중 제작에 최신 기준을 적용한다.
