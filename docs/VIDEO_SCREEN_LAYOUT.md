# 화면 구성 규격

제작 순서·승인·비중·재검수는 [통합 제작 규칙](VIDEO_WORKFLOW.md), 설명 화면 구현은 [화면 규격](VIDEO_VISUAL_STYLE.md)을 따른다.

1. 원래 고양이 로고 인트로2초. 기존 승인 렌더를 재사용한다. 없을 때만 `shared/assets/branding/yamyamcoding-cats-original.png` 원본으로 재구성하고 브라우저 UI/알림 배지는 넣지 않는다.
2. 전체 개론: 중심 질문·얻는 점·실제2–3단계 순서·첫 사례 연결을 자연스러운2–4문장으로 안내한다. 약20–30초 계획이며 본편의 화면 역할로 분류한다.
3. 실제 게임은 전체 화면. PPT 액자 속 작은 영상으로 넣지 않는다. 원본 색·비율·핵심 UI/행동을 보존하고 의미 있는 추적 표식을 해설과 함께 표시한다.
4. 설명은 프로젝트 팔레트와 상세 대상·계산/동작/결과 비교를 유지하며, 내용에 따라 Manim·Three.js·Motion Canvas·Blender/엔진을 선택한다. 2.5D를 의무화하지 않는다. 현재 렌더링 역사1편 수정본은 Three.js의 실제3D 설명을 사용한다. 신규/렌더링 역사 지정 수정본은 검정/흰 글씨, 별도 승인된 기존 흰 프로젝트는 보존한다.
5. 원본 회원 엔딩10초: 왼쪽 감사 문구/안내, 오른쪽 원본 회원 행, 원래 로고. 프로필·이름·배지/정확 제목을 보존하고 플랫폼3요소 공간을 확보한다.

모든 내레이션 자막은 `(960,970)` / MC `(0,430)` 고정. 박스·그림자 영역을 설계 맨 처음 확보한다. 게임 crop/소스/큐/설명 레이아웃을 고치며 자막을 이동하지 않는다. 본편60:40의 제외 구간은 branding2초와 member10초뿐이다. 개별 예외는 manifest의 사용자 승인 계약을 따른다.
