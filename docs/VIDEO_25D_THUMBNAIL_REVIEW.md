## 설명 화면

흰 연구 발표 스타일과 읽기 쉬운 제목은 유지한다. 물체의 윗면·옆면·두께, 바닥에 놓인 관계, 앞뒤 가림, 시점에 따른 상대 이동이 실제 화면에 보여야 한다. 그림자만 붙인 사각형·정적인 카드 배열은 이 요구를 충족하지 않는다. 대사의 핵심 관계를 입체 모델·공간 비교·진행 경로로 설명하고 내레이션의 해당 문단에서 실제로 움직인다. 장면별 독립 Motion Canvas 파일을 유지한다.

렌더된 초반/중반/후반과 모든 문단 변화 지점을 직접 읽고 비교한다. 움직임이 개념을 설명하는지, 한글 자막 자리 `(960,970)`와 그림/글자가 겹치지 않는지 검수한다. 코드에 2.5D라고 적혀 있거나 자동 프레임 검사만 통과한 것으로 승인하지 않는다.

자막을 제외한 raw preflight만으로 배치를 승인하지 않는다. 같은 실제 ASS와 최종 타임스탬프를 적용한 preflight에서 두 줄 자막 위의 문구, 입체 바닥의 끝과 보조 문구 사이 여백도 직접 확인한다. 멀미 수정본의 raw 도식은 읽혔지만 최종 자막이 y365–375 문구를 가린 실제 실패를 보존한다. 내레이션 자막을 움직이지 않고 프로젝트 내부의 투영 원점·크기·도식 글자 배치를 고친다. 이전 소스·렌더·검수는 별도 보존하고 수정본의 전체 최종 픽셀 승인은 다시 수행한다.

## 썸네일

사용자 채널 화면의 좋은 예시는 `게임을 베끼면 재미도 같을까?`, `공격이 답답한 이유? 프레임을 보세요`, 기존 원버튼 게임 썸네일이다. 저장된 직접 참조는 `projects/deconstruct-analyze-rebuild/publishing/thumbnail-v2.png`, `projects/counting-animation-frames/publishing/thumbnail-v3.png`다.

얇은 노란 상단 띠, 흰 배경, 전화기 크기에서도 읽히는 큰 검정 제목과 핵심 빨강 강조를 유지한다. 상단에 `얌얌코딩`을 표시한다. 원래 검정·주황·흰 고양이 정체성이 그림 안에서 관찰·응원·설계 행동을 하는 자연스러운 주인공이 되도록 한다. 해당 영상의 한 가지 질문을 개성 있는 삽화로 설명한다. 영상 캡처 사각형, 재생기 액자, PPT 카드/통계표, 별개 원형 로고를 붙인 구성으로 대체하지 않는다.

생성 썸네일도 실제 한글·주제·마스코트·작은 크기 가독성을 직접 확인한다. 승인 전에는 prepared로 기록한다. Git은 검토한 전달 썸네일의 정확한 파일만 필수 이미지로 등록하며, 탐색·QA 이미지는 로컬에 보존한다.
