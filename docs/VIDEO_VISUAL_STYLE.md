# 화면·2.5D 제작 규격

운영·승인·재검수 범위는 [통합 제작 규칙](VIDEO_WORKFLOW.md)만 따른다. 이 문서는 장면 설계 때 적용하는 화면 규격이다.

## 팔레트와 글자

신규 설명은 `research-black-v1` / `motion-canvas/src/styles/research-dark.ts`를 사용한다. 이미 승인된 흰 프로젝트는 `research-paper.ts`를 보존한다. 명시 수정된 `game-lighting-history-01`~`04`는 검정이다. 실제 게임·브랜딩·회원 엔딩·썸네일을 함께 검게 바꾸지 않는다.

| 역할 | 색 |
|---|---|
| 배경 | #000000 |
| 본문·수식·라벨 | #f5f5f5 |
| 보조·축 | #b8b8b8 |
| 제목·강조 | #e8cf83 |
| 벡터·곡선 | #73c7c2 |
| 초점 | #f39a4b |
| 구분선 | #6b7280 |
| 입체 윗면/앞면/옆면 | #34454b / #243239 / #162026 |

빨강·초록 등 추가 색은 역할·라벨을 정해 사용한다. 색만으로 의미를 구분하지 않는다. 1920×1080 좌우 안전 여백96px, 제목48–56px, 핵심 라벨32–40px, 보조26–30px가 시작값이다. 영어Segoe UI, 한글Malgun Gothic, 수식Cambria Math, 코드Consolas 또는 승인 폰트를 사용한다. 실제 폰트로 폭을 측정한다. 하단 고정 자막의 박스와 그림자 공간을 먼저 예약하고 요약 띠·수식은 그 위에 놓는다. 이전 흰 레이아웃의 y405 요약 띠를 그대로 복사하지 않는다.

## 상세 대상과 실제 공간 표현

- 사람: 머리·얼굴 또는 장비, 몸통·의복, 어깨/팔꿈치/무릎 등 관절, 손발, 대사와 맞는 자세·행동을 알아볼 수 있게 제작한다.
- 물건: 비례·윤곽과 특징적 구조/작동부를 그린다. 자전거의 프레임/바퀴/핸들/페달, 항공기의 동체/조종석/주익/꼬리처럼 동작을 이해하는 세부를 포함한다.
- 같은 대상을 연결되는 씬에서 재사용하고 투영·앞뒤 가림·면·높이·관절 동작을 일관되게 유지한다. 사람/탈것이라는 이름만 붙인 큐브·막대 아이콘은 대체물이 아니다. 큐브/경계상자/행렬칸 자체를 설명할 때는 추상 도형이 적합하다.
- 카드에 그림자만 주면2.5D가 아니다. 실제 투영된 면, 공간 관계·가림, 내레이션에 맞는 이동/회전/비교가 보여야 한다. 과도한 장식·네온·빛번짐보다 대상과 수식의 대비를 우선한다.
- 장면별 실제 대상/식별 세부/관절·작동부/시작·끝 상태/대사별 움직임/같은 대상의 연결/자막 공간을 제작 전에 적는다. 독립 Motion Canvas 씬과 편집 가능한 자산을 사용한다. 필요한 수학 전개는 Manim으로 만들되 동일 팔레트·타이밍을 따른다.

## 실제 게임 위의 해설

게임은 전체 화면, 원래 색과 동작을 유지한다. 핵심 빨간선, 구별되는 축·벡터·각도·궤적·영역/라벨을 대사 순서로 등장시킨다. 실제 대상과 카메라를 추적하고 컷이 바뀌면 이전 표식을 제거한다. 게임 디자인에는 상태·윤곽·선택을 표시하고 무관한 수식을 넣지 않는다. 화면상의 투영 길이/각도를 확인되지 않은 게임 월드 값으로 주장하지 않는다.

실제 자막을 합성한 대표 동작과 까다로운 UI 구간을 먼저 확인한다. 최종에는 모든 관련 움직임·큐/컷을 한 번 통합 검수하고 해시/구간을 기록한다. 정지판이나 코드 이름은 움직임 승인 근거가 아니다. 변경 없는 승인 구간은 통합 규칙의 재사용 조건으로 유지한다. 썸네일은 [별도 채널 삽화 규격](VIDEO_25D_THUMBNAIL_REVIEW.md)을 따른다.
