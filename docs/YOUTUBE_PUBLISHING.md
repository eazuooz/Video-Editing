# YouTube 게시 규격

현재 한 편 자동 완료 범위는 [통합 제작 규칙](VIDEO_WORKFLOW.md)과 `shared/publishing/video-production-control.json`이 우선한다. 2026-10-14 사용자 지시로 자체 검수한 전체 captioned MP4를 **먼저 Google Drive에 올려 최종 사용자 검수**를 받는다. 파일 ID·버전·SHA256·재생/접근 확인·사용자 확인을 기존 원장에 연결한다. 해당 버전 확인 후 같은 파일의 YouTube 비공개 업로드와 가능한 설정 저장·재열람을 진행하며 단계별 승인을 반복하지 않는다. 자동 채팅과 다음 편 자동 착수는 꺼 둔다. 공개·예약·기존 업로드 교체/삭제는 별도 명시 범위가 필요하며 기존 업로드는 보존한다.

2026-10-15 사용자 정정: **YouTube에는 1920×1080·60fps captioned 제작 마스터를 업로드한다.** 모바일 확인을 위해 만든720p/30fps 압축본을 게시 파일로 선택하지 않는다. Drive에 압축 검수본을 제공한 경우, 승인된 버전의 원본 마스터 SHA256과 검수본 SHA256·변환 설정·내용/타이밍 대응 검사를 연결한다. 이 경우 '같은 파일'은 재편집하지 않은 같은 승인 버전의 제작 마스터를 뜻하며 압축본 바이트를 게시하라는 뜻이 아니다. 내용·음성·자막·편집이 달라지면 새 검수가 필요하다.

## 업로드 전에 준비할 하나의 패키지

- `output/<slug>/<slug>.captioned.mp4`의 현재 검수/해시와1920×1080·60fps 실측, clean·KO·EN 수집. Drive 원본이면 동일 해시, 압축 검수본이면 승인된 제작 마스터와의 변환 대응 증거를 연결한다. clean/모바일 압축본 업로드 금지. 기존 실제 ID/진행 중 업로드부터 확인해 중복 업로드하지 않는다.
- [채널 삽화 썸네일](VIDEO_25D_THUMBNAIL_REVIEW.md): 자연스러운 고양이/얌얌코딩, 노란 띠·흰 바탕·큰 검정/빨강 제목; PPT/영상 inset 제외.
- 시청자의 문제·궁금증을 앞세우고 실제 내용과 정확한 주제 검색어로 보완한 KO/EN 제목. 아래 `viewer-question-first-titles-v1`을 적용하며 검색 순위/성과를 보장하지 않는다.
- 새 설명과 실측00:00 시작 챕터를 기존 채널 소개 위에 한 번만 추가한다. 과외·Discord·회원 canonical URL은 `shared/publishing/youtube-defaults.json` 및 채널 소개 원문에서 정확히 복사한다. 미작성 노트/GitHub 자리표시는 제외한다.
- `description-sources-last-v1`(2026-10-19): **출처·자료·제작 도구 목록을 한글·영어 전체 설명란의 절대 맨 아래에 항상 추가한다.** 실제 사용·참고한 영상, 이미지·자산, 음악, 제작 도구와 기술 자료 중 해당 항목을 기존 계획·출처/권리 기록과 대조해 원본 URL·제작자와 의무 라이선스/attribution 문구를 쓴다. 실제 사용하지 않은 후보·추정 도구·가짜 출처와 불필요한 제작자 이력은 넣지 않는다. 출처는 영상 소개·실측 챕터·태그·기존 채널/코칭/Discord/회원 안내 등 모든 본문과 footer **뒤**에 놓으며, 출처 뒤에는 어떤 footer도 붙이지 않는다. 대본·자막·설명 화면의 참고 제작자/각색 언급 금지와 내부 기록 보존은 그대로다. 현재 선택 D21 수정본과 향후 승인된 업로드에 적용하고 기존 게시 영상은 일괄 수정하지 않는다.
- `description-only-source-credits-v1`(2026-10-19): **쇼츠·일반 영상·강의 모두 영상 안에 편집자가 추가한 출처·제작자·URL·제작 도구 크레딧 띠를 넣지 않는다.** 전체 KO/EN 설명란의 절대 맨 아래에 위 검증 출처·라이선스/attribution을 온전히 남기며 내부 출처·권리·해시 기록도 유지한다. 내용 이해에 필요한 게임명·정식 용어·조건/결과·`해설용` 표시와 원본 게임 UI는 유지한다. 원본에 포함된 제3자 워터마크·의무 표시를 지우거나 가리지 않고, 화면 표시가 사용 조건이면 설명란 표시로 사용 가능한 대체 자료 또는 명시 허가를 확보한다. 현재 선택 좀비 쇼츠 수정과 이후 명시 선택 제작·수정에 적용하며 기존 게시 영상 일괄 재제작/설정 변경은 하지 않는다.
- 공용 준비 도구의 receipt에는 `sourceCredits: {ko: "확인한 출처 본문", en: "verified credits body"}`를 넣는다. 도구는 본문 안의 명시적인 기존 출처 절을 보존해 분리하고, 영상 본문/챕터→채널 안내→출처 순서로 조립한다. 필수 표시는 정확한 원문을 보존하고 두 언어가 빠지거나 전체5000자 제한을 넘으면 조용히 삭제·잘라내지 않고 준비 오류로 알린다. 실제 자료의 사용 여부·권리 검토는 기존 제작 기록으로 확인하며 URL이 있다는 이유만으로 사용 허가를 추정하지 않는다.

## 제목: 시청자의 문제와 궁금증부터

`viewer-question-first-titles-v1` · 2026-10-16 사용자 제공 채널 비교 분석을 바탕으로 추가했다. 그 분석의 수치를 이번 규칙 작업에서 새로 검증한 것으로 기록하지 않는다. 운영 범위는 [통합 규칙](VIDEO_WORKFLOW.md)을 따른다.

- **먼저 시청 이유를 보여 준다.** ‘무엇을 가르치는가’에 앞서 시청자가 겪는 구체적 상황·불편·의외의 현상·원하는 결과를 표현한다. 주제의 실제 독자를 겨냥하며 일반 게이머에게 적용되지 않는 강의를 억지로 대중 주제로 포장하지 않는다.
- **주제는 정확하게 남긴다.** 필요한 게임명·검색어·정식 기술 용어는 뒤쪽이나 자연스러운 문맥으로 보완한다. 목차 나열·전문 용어·편 번호만으로 시작하는 제목을 기본값으로 삼지 않는다. 모든 제목을 ‘왜 ~일까?’로 통일하지 않는다. 영어 제목도 같은 약속과 범위를 자연스럽게 전달한다.
- **약속을 대본과 맞춘다.** 기존 게시안에 서로 다른 관점의 후보2–3개, 대상 시청자, 실제로 답하는 대목과 선택 이유를 기록한다. 근거 없는 최상급·확정적 원인·자극적인 단정·가짜 수치나 시간 제한으로 클릭을 유도하지 않는다. 예시의 ‘10분’도 영상에서 뒷받침되지 않으면 쓰지 않는다. 제목을 쉽게 바꾼다고 본문의 전문 내용을 삭제하지 않는다.
- **썸네일은 같은 궁금증을 그림으로 보완한다.** 제목 전체를 되풀이하기보다 한 가지 상황·대조·결과와 짧은 핵심 문구로 연결한다. 기존 얌얌코딩 색·고양이·한글 가독성 규칙을 유지한다. 제목만 변경하는 실험에서는 썸네일을 동시에 변경하지 않는다. 둘을 함께 바꿨다면 결합 변경으로 기록하고 어느 요소의 효과인지 단정하지 않는다.
- **성과는 비교 조건과 함께 읽는다.** 기존 원장에 관찰 시각, 공개 후 경과, 유입 경로, 노출수·CTR·조회수·30초 및 전체 시청 유지/평균 시청시간을 가능한 범위에서 기록한다. 서로 다른 영상은 기본 첫24시간처럼 같은 경과 구간으로 비교하고 누적 수치와 섞지 않는다. 제목 수정 전후는 같은 길이의 관찰 구간으로 기록하되 영상 나이·노출 대상·유입 경로·동시 변경 차이를 명시한다. 작은 표본, CTR 단독 또는 초반 유지율만으로 추천 원인·전체 재미·품질 저하를 확정하지 않는다. 노출 증가나 조회수 개선을 보장하지 않는다.

| 내용 중심 제목 | 시청 이유를 앞세운 후보 예시 |
|---|---|
| 계층형 아웃라인으로 게임 기획서 정리하기 | 게임 아이디어가 많을수록 기획서가 엉키는 이유 |
| 게임 멀미와 카메라 설계 | 어떤 게임은 조금만 해도 멀미가 나는 이유 |

예시는 후보이며 기존 영상에 적용 완료한 제목이 아니다. 새 영상과 사용자가 선택한 수정에 적용하고, 기존 업로드 변경은 해당 범위가 지정됐을 때 한 편씩 수행한다. 실제 저장 시 이전/새 제목·썸네일 버전·변경 시각·검증할 가설을 기존 receipt/검수 원장에 남긴다. 내용상 결함이 확인되지 않았다면 제목·썸네일 가설을 먼저 검증하고 영상 전체를 재제작하지 않는다. 이 규칙 자체는 플랫폼 변경·A/B 테스트 실행·자동 분석 일정을 승인하거나 추가 승인 절차를 만들지 않는다.

UI는 CUA로 조작한다. 한 개 captioned 파일을 한 번 비공개 저장한 뒤 같은 실제 ID에서 설정을 마친다.

|---|---|
| 파일/공개 상태 | 실제ID·제목·비공개/예약 없음(예약 별도 승인 시 해당 상태)·SD/HD 처리 |
| 영구자막·화면 출처 | 플레이어 CCoff에서 실제 게임/설명 픽셀의 하단 고정 한글. 편집자가 더한 출처/크레딧 띠 없음, 고양이·핵심 대상 가림 없음. 원본 워터마크/의무 표시 보존 |
| 언어 | 영상 한국어, KO/EN 각각 수동 SRT 게시, 영어 제목·설명 별도 저장·재열람 |
| 썸네일 | 현재 파일의 실제 적용·재열람, 모바일 가독성 |

| 00:00 카드 | 과외 URL·제목/티저 `프로그래밍 과외`, 실제 시작 시점 |

계정/플랫폼 외부링크 제한이면 실제 제한을 기록하고 영상 끝 안내/설명 링크를 유지한다. 제목이나 추측 URL로 playlist ID를 만들어내지 않는다. 실제UI 프레임 시간 기준을 확인하고 30/60fps 입력을 추측하지 않는다.

설정 JSON이나 업로드 완료율은 저장 후 재열람을 대신하지 않는다. `publishing/youtube-upload.json` 또는 프로젝트의 현재 receipt에 실제 상태와 최소 증거를 기록한다. 관찰하지 않은 wizard modal·사람 청취·발음·공개 권리를 true로 바꾸지 않는다. 같은 저장상태를 증거 수를 늘리기 위해 재설정하지 않는다.

## 플랫폼 후속과 예약

비공개 댓글은 원문 준비만 하고 `pending-video-publication`으로 둔다. 댓글 때문에 공개하지 않는다. 별도 승인된 댓글 등록/고정은 실제 가능한 상태에서 수행하고 실제ID/고정표시를 기록한다.

썸네일 한도는 prepared파일·실제ID·제한·재시도 시각을 별도 후속으로 남긴다. 나머지 해당 편 설정/Git은 수행하되 thumbnail/fullSettings는 실제 저장까지 false다. 우회·빠른 반복·중복 업로드·다음 편 자동 착수를 하지 않는다. 선택형CC 전파·자동더빙 미확인도 별도 pending으로 남긴다.

해당 편의 예약이 승인된 경우만 디자인/게임강의 일일 교대09:00 Asia/Seoul 기준과 `shared/publishing/daily-alternating-schedule.json`, 실제 Studio/시리즈 순서를 대조한다. 기존 날짜를 보존하고 중복 배정·미완성 예약을 하지 않는다. 실제 저장 후 날짜/시간/GMT+0900을 다시 열어 확인한다. 현재 있는 예약은 자동 채팅 중단과 무관하게 그대로 둔다.

교체는 승인된 정확한 baseline→replacement 관계로만 진행한다. 완성 교체본/설정/Git/실제 예약 검증 전 원본 삭제 금지. 옛 업로드 삭제가 별도 사용자 확인 대기이면 그대로 둔다. 새 수동 확인 경계를 옛 일괄 삭제 지시로 넘지 않는다.

준비 도구: `node scripts/prepare-youtube-upload.cjs <slug>`(로컬 준비), 실제 플랫폼 조작/검증은 별도다. 이 문서 수정은 YouTube 상태를 바꾸지 않는다.
