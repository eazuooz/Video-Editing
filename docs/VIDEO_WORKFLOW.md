# 통합 영상 제작 규칙 — 한 편씩 제작·로컬 최종 검수·업로드

정책 `preproduction-first-v1` · 2026-10-13 사용자 요청으로 기존 누적 규칙을 통합했다. 이 문서는 현재 운영의 단일 기준이다. 세부 문서는 수치·구현 참조이며 별도 승인 절차를 추가하지 않는다. 과거 원문과 완료 이력은 [이전 규칙 보관 목록](history/video-policy-before-20261013-consolidation/manifest.json)에 바이트 그대로 보존했다. 이력은 필요한 사건을 찾을 때만 읽는다.

## 1. 작업 범위와 사용자 확인

현재 운영 상태는 `shared/publishing/video-production-control.json`이다. 사용자가 제작·수정할 한 편을 지정하면 **기획·자료 확보·대본·PPT·음성·편집·자체 검수·4파일 납품·로컬 최종 검수 링크·선택 Git 전달까지 중간 승인 없이 완료**한다. 2026-10-19 사용자 지시 “폴더 링크줘~ 드라이브로 안올려줘도 돼 이제는 규칙에서 제거해줘”에 따라 기본 검수 전달은 **로컬 출력 폴더와 전체 자막영상 링크**로 한다. Google Drive는 이후 명시 요청이 있을 때만 업로드하며 필수 검수 게이트가 아니다. **같은 SHA256 완성본에 대한 사용자 확인·수정 반영을 마친 뒤 YouTube에 업로드**한다. 대본·샘플마다 승인받는 방식은 되살리지 않는다.

제작 전 설계표와 대표 샘플은 오류를 예방하는 **내부 품질 확인**이다. 대본·샘플·TTS·렌더 단계마다 진행 승인을 다시 묻지 않는다. 사용자에게 요청할 최종 확인은 실제로 재생 가능한 로컬 전체 완성본과 출력 폴더 링크를 준비한 뒤 한 번 받는다. 실제 필수 입력이 없거나 해결할 수 없는 장애는 구체적으로 알린다. 시간 경과나 답변 없음은 검수 승인이 아니며, 기술 검사 통과나 링크 전달을 사람 청취 승인으로 바꾸지 않는다.

자체 검수가 끝난 한 편의 로컬 출력 폴더·전체 자막영상 링크·SHA256·남은 항목을 보고하고 최종 사용자 검수를 기다린다. 확인 후에는 승인된 같은 파일로 YouTube 비공개 업로드와 가능한 설정을 마친다. 다음 편은 자동 시작하지 않는다. 자동 채팅/heartbeat는 계속 꺼 둔다. 공개·예약·기존 업로드 교체/삭제는 별도 명시 지시를 따른다. 기존 큐의 ACTIVE/queued나 옛 일괄 지시로 다른 편을 재개하지 않는다.

착수 지시는 실제 사용자 메시지·일시·선택한 영상과 범위를 기록한다. 빈 템플릿이나 시간 경과는 새 영상 선택이 아니다. 2026-10-16 사용자의 작업 창구 통합 지시에 따라 게임디자인·렌더링 특별편·게임수학은 현재 채팅과 `D:/Github/VideoEditing`에서만 제작·검수·상태 갱신한다. [전체 작업표](VIDEO_WORKLIST.md)와 `shared/publishing/video-worklist.json`에서 시리즈 순서, 제작 완료, 최신 규칙 검수, 사용자 승인, 플랫폼 상태를 구분한다. 기존 다른 컴퓨터의 제작 채팅은 이력 확인용이며 새 작업을 전달하거나 자동 재개하지 않는다. 현재 실행 선택은 운영 상태 파일을 따른다. 작업표에 포함됐다는 이유만으로 모든 편을 착수하지 않으며 기존 미선택 영상과 예약은 보존한다. 연구와 다른 작업의 프로세스·파일·스테이징은 보존하며 강제 종료하지 않는다.

## 2. 재개 시 최소 읽기와 단일 기록

매번 현재 운영 상태 → 해당 편의 `project.json` → 최신 체크포인트 → 이번 단계에 필요한 입력/검수 항목만 읽는다. 같은 세션에서 읽은 규칙과 변경 없는 본문은 반복 출력하지 않는다. 중복 검토는 최초에 전체 기존 목록과 실제 채널 기록으로 후보를 좁힌 뒤 관련 전체 대본·질문·주장을 대조한다. 이후에는 현재 검사에서 달라진 관련 입력만 읽고 이전 검토를 해시로 재사용한다. 제목/ID가 다르다는 이유만으로 distinct로 판정하지 않는다.

새 영상은 `planning/production-plan.json`과 `planning/outline.md`를 사용한다. JSON은 승인·경로·단계 상태, outline은 사용자에게 보여 줄 대본/장면 설계다. 이미 상세 계획이 있는 프로젝트는 같은 내용을 복사하지 말고 기존 파일을 참조한다. `production/review-ledger.json` 한 곳에 각 검사의 입력 해시·범위·방법·결과·근거를 연결하고, 체크포인트는 현재 단계·실제 작업 식별자·막힌 이유·다음 한 작업만 기록한다. 과거 체크포인트를 본문에 계속 덧붙이지 않는다.

다음 단계의 입력이 바뀌었거나 실제 실패가 있을 때만 검사를 추가한다. 문서/메타데이터 정리 때문에 음성·게임 원본·렌더를 다시 만들지 않는다. 새 규칙 추가도 기존 항목을 수정하고 변경 이유를 짧게 남기며 날짜별 중복 지시를 쌓지 않는다.

## 3. 제작 전에 해결할 품질 기준

다음 표를 채운 설계가 제작의 입력이다. 최종 검수에서 처음 발견할 항목으로 미루지 않는다.

2026-10-17 사용자 지시 `explanation-visual-evidence-v1`: **PPT·설명의 각 핵심 내용에 알맞은 스크린샷·그림·도식을 함께 넣어, 말하는 대상과 행동·결과를 눈으로 이해하게 한다.** 구체적인 게임 설명은 직접 확인한 독립 게임 화면을 우선하고, 추상적인 관계는 직접 만든 도식이나 권리를 확인한 그림으로 풀어낸다. 설명 순서에 맞춰 이미지를 보여 주거나 교체하고 실제 대상에 라벨·화살표·윤곽선을 연결한다. 단순 장식이나 화면 수를 채우기 위한 이미지는 넣지 않는다. 기존 씬 계획에 이미지의 설명 목적·출처/추출 시점·대사 큐·크롭·자막 여백을 기록하고 실제1080p와375px 모바일 및 움직이는 전환을 확인한다. 스크린샷 중심 설명은 설명 분량으로 계산하며, 시각 요소만 바꿀 때는 같은 음성·타이밍 검증을 재사용한다. [화면 규격](VIDEO_VISUAL_STYLE.md)의 세부 기준을 현재 선택 수정본과 이후 신규 제작에 적용하며 새 승인 단계나 미선택 영상 재제작은 추가하지 않는다.

2026-10-15 사용자 지시 `high-school-to-specialist-v1`: **모든 설명은 고등학생도 이해할 수 있는 구체적 상황에서 시작해, 필요한 전공 수준의 원리·수식·구현까지 단계적으로 올라간다.** 익숙한 사례와 관찰 → 필요한 선행 개념·용어·기호 정의 → 한 변수만 바꾼 원인과 결과 → 작은 수치 예제 → 일반식·실제 구현 → 적용 한계 순서로 연결한다. 주제에 필요 없는 단계를 형식적으로 늘리지 않되, ‘기저=기준 방향’처럼 이름만 풀어 쓰고 계산으로 건너뛰지 않는다. 화살표의 대상과 좌표계, 값이 달라지는 이유, 계산 결과가 화면의 무엇을 바꾸는지 말과 화면으로 함께 보여 준다. 쉬운 시작을 위해 유용한 전문 내용을 삭제하지 않고 이해에 필요한 시간을 확보한다. 2026-10-20 사용자 지시 `article-faithful-teaching-pace-v1`에 따라 한 개념을 먼저 설명한 뒤 애니메이션·그림으로 대상→변화→결과를 순차적으로 보여 주고, 실제 읽기·관찰 시간을 둔 후 짧게 결과를 확인하고 다음 단계로 간다. 숫자·공식·코드를 빠르게 낭독하는 것으로 설명을 대신하지 않고 뜻과 작은 예시를 풀어 준다. 기존 `learningSteps`에 연결된 `teachingBeats`에서 `speech`(말할 설명), `visual`(보여 줄 대상·변화·결과), `hold`(읽기·관찰 목적과 계획 시간)를 구분하고, 제작 후 실측 시간·검수 범위를 기록한다. 모든 문장에 동일한 침묵을 붙이거나 총 길이를 제한하지 않으며 자연스러운 연속 발화와 문장 호흡을 유지한다. 다음 설명 연결과 초심자의 단계별 이해·전문적 정확성을 함께 검수한다. 현재 선택 대본과 향후 명시 선택 작업에 적용하며 새 승인 절차나 미선택 영상의 자동 재제작은 추가하지 않는다.

같은 날 추가된 `canonical-technical-terms-v1`: **쉬운 설명에서도 정식 기술 용어를 정확히 사용한다.** 처음에 정식 용어와 쉬운 뜻을 함께 설명하고 화면에는 한글·영문과 필요한 약어를 표시한다. 이후 대본·한영 자막·UI는 같은 표기를 유지한다. 기존 계획의 `terminology`에 정식 명칭/1차 근거/뜻/첫 등장/허용 약칭/발음 별칭을 기록한다. 예: 섀도 맵(Shadow Map), 캐스케이드 섀도 맵(Cascaded Shadow Maps, CSM), 라이트맵(Lightmap), 법선(Normal), 내적(Dot Product). ‘캐스케이드 맵’처럼 대상을 흐리는 생략이나 라이트맵·섀도 맵의 혼용을 피한다. 발음용 별칭은 화면 철자를 바꾸지 않으며 실제 TTS와 인코딩 자막에서도 수정 용어를 검수한다.

현재 선택한 `game-lighting-history-01` 수정본은 사용자 요청에 따라 **설명43%·실제 영상57%**를 적용한다. 인트로2초·회원10초를 제외한 본편 프레임으로 계산하고 최대1프레임 반올림만 허용한다. 이 예외는 이 영상에만 적용하며 다른 영상의 기본60:40은 유지한다. 필요한 설명 보강과 관련 장면 재편집으로 맞추고 무의미한 정지·반복·느린 재생으로 비율을 채우지 않는다.

## 5. 제작 실행과 타이밍 확정

1. 현재 PID뿐 아니라 명령줄·생성시각·세션·로그로 살아 있는 작업을 확인한다. 종료된 작업을 기다리거나 새로 중복 실행하지 않는다. 무거운 TTS/합성/렌더/업로드는 한 번에 하나씩 실행한다. 승인된 현재 편만 진행한다.
2. 동일 Qwen3-TTS1.7B/레퍼런스로 장면 단위 연속 발화를 생성한다. 기존 동일 대본의 승인 PCM은 재사용한다. 발화 앞에 게임 예시 길이만큼 무음을 넣지 않는다. 연구 GPU는 현재 학습 완료/체크포인트 봉인 뒤 협력 인계하고 성공·실패 모두 자신이 정지시킨 미완료 큐만 복원·실제 재개 확인한다. 완료 연구는 재시작하지 않는다.
3. 현재 PCM의 전체 ASR을 한 번 실행해 실제 전체 문장을 대본과 직접 대조한다. 누락·반복·숫자·고유명사·임의 인사·끝소리를 확인하고 발화 중 국소 음량 급락과 문단/씬 간 레벨 차이도 한 번 측정한다. 의심 구간만 독립 완결 문맥과 실제 PCM으로 해소한다. ASR chunk 경계/역행 타임스탬프 오류를 실제 반복으로 단정하지 않는다. endingHeuristic만으로 승인하거나 예상 대본을 인식 prompt에 넣지 않는다.
4. 실측 음성으로 단일 프레임 타임라인을 확정한다. 컷·씬 시작·믹스·KOEN SRT·챕터·회원 엔딩을 함께 갱신하고 해시로 잠근다. 두 언어의 큐 수는 달라도 전체 문단 대응과 발화 경계는 일치해야 한다. 차이가 있으면 `captionAlignmentReview`의 전체 큐 매핑을 사용한다.
5. 승인 음성·음악/원음 계약으로 믹스하고 현재 최종 믹스의 전체 ASR을 한 번 직접 대조한다. 원본 PCM→처리된 내레이션 트랙→최종 인코딩의 같은 발화 시각을 비교해 목소리 급락·배경 가림·페이드/덕킹/리미터에 의한 감쇠를 확인한다. 전체 LUFS·피크나 ASR 통과만으로 국소 음량을 승인하지 않는다. 의심 구간은 앞뒤 문맥의 실제 재생·청취와 측정으로 해소하고 기존 믹스 보고서/검수 원장에 기록한다. 상세 기준은 [오디오 규격](NARRATION_AUDIO_STANDARD.md)의 `narration-level-continuity-v1`을 따른다. unmixed 승인으로 대체하지 않고 동일 믹스를 또 인식하지 않는다. 음악/화자 선택 승인, 라이선스 확인, 사람 청취는 서로 별개다.
6. 씬별 실제 자막/정확 crop/현재 타이밍으로 합성 전 충돌 검사 후 clean/captioned 최종 쌍을 생성한다. 이미 승인한 씬은 재렌더하지 않는다. 프리뷰·무음 visual·prepared 상태를 최종 완료로 기록하지 않는다.
