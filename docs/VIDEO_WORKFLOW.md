# 통합 영상 제작 규칙 — 한 편씩 제작부터 비공개 업로드까지 완료

정책 `preproduction-first-v1` · 2026-10-13 사용자 요청으로 기존 누적 규칙을 통합했다. 이 문서는 현재 운영의 단일 기준이다. 세부 문서는 수치·구현 참조이며 별도 승인 절차를 추가하지 않는다. 과거 원문과 완료 이력은 [이전 규칙 보관 목록](history/video-policy-before-20261013-consolidation/manifest.json)에 바이트 그대로 보존했다. 이력은 필요한 사건을 찾을 때만 읽는다.

## 1. 작업 범위와 사용자 확인

현재 운영 상태는 `shared/publishing/video-production-control.json`이다. 사용자가 제작·수정할 한 편을 지정하면 **기획·자료 확보·대본·PPT·음성·편집·자체 검수·4파일 납품·비공개 업로드와 가능한 설정·선택 Git 전달까지 중간 승인 없이 자동으로 완료**한다. 사용자는 완성된 비공개 영상을 검수한 뒤 수정 여부를 결정한다. 2026-10-13 최신 지시에 따라 이전 제작 전/완성본의 두 차례 승인 대기 절차를 대체한다.

제작 전 설계표와 대표 샘플은 오류를 예방하는 **내부 품질 확인**이다. 대본·샘플·TTS·렌더·업로드 단계마다 사용자에게 진행 승인을 다시 묻거나 멈추지 않는다. 실제 필수 입력이 없거나 해결할 수 없는 장애, 별도 확인이 반드시 필요한 작업만 구체적으로 알린다. 완료 전 상태를 완료나 사람 청취 승인으로 바꾸지는 않는다.

한 편 완료 후 실제 비공개 링크와 납품 파일·남은 항목을 보고하고 사용자 검수를 기다린다. 다음 편은 자동 시작하지 않는다. 자동 채팅/heartbeat는 계속 꺼 둔다. 공개·예약·기존 업로드 교체/삭제는 이 한 편 자동 제작 범위에 포함하지 않고 별도 명시 지시를 따른다. 기존 큐의 ACTIVE/queued나 옛 일괄 지시로 다른 편을 재개하지 않는다.

착수 지시는 실제 사용자 메시지·일시·선택한 영상과 범위를 기록한다. 빈 템플릿이나 시간 경과는 새 영상 선택이 아니다. 현재 계층형 영상은 제작부터 비공개 업로드까지 명시 승인된 한 편으로 마무리한다. 기존 미선택 영상과 예약은 보존한다. 연구와 다른 작업의 프로세스·파일·스테이징은 보존하며 강제 종료하지 않는다.

## 2. 재개 시 최소 읽기와 단일 기록

매번 현재 운영 상태 → 해당 편의 `project.json` → 최신 체크포인트 → 이번 단계에 필요한 입력/검수 항목만 읽는다. 같은 세션에서 읽은 규칙과 변경 없는 본문은 반복 출력하지 않는다. 중복 검토는 최초에 전체 기존 목록과 실제 채널 기록으로 후보를 좁힌 뒤 관련 전체 대본·질문·주장을 대조한다. 이후에는 현재 검사에서 달라진 관련 입력만 읽고 이전 검토를 해시로 재사용한다. 제목/ID가 다르다는 이유만으로 distinct로 판정하지 않는다.

새 영상은 `planning/production-plan.json`과 `planning/outline.md`를 사용한다. JSON은 승인·경로·단계 상태, outline은 사용자에게 보여 줄 대본/장면 설계다. 이미 상세 계획이 있는 프로젝트는 같은 내용을 복사하지 말고 기존 파일을 참조한다. `production/review-ledger.json` 한 곳에 각 검사의 입력 해시·범위·방법·결과·근거를 연결하고, 체크포인트는 현재 단계·실제 작업 식별자·막힌 이유·다음 한 작업만 기록한다. 과거 체크포인트를 본문에 계속 덧붙이지 않는다.

다음 단계의 입력이 바뀌었거나 실제 실패가 있을 때만 검사를 추가한다. 문서/메타데이터 정리 때문에 음성·게임 원본·렌더를 다시 만들지 않는다. 새 규칙 추가도 기존 항목을 수정하고 변경 이유를 짧게 남기며 날짜별 중복 지시를 쌓지 않는다.

기본 제작 방법은 **마사히로 원본의 짜임새·사례 참고 → 같은 게임의 실제 플레이 영상을 별도로 검색·확보 → 우리 내레이션과 직접 만든 상세 PPT를 더해 편집**이다. 오래된 게임은 같은 설명이 성립하는 동일 시리즈 최신 버전을 검토한다. 참고 영상 자체의 화면·게임 컷·PPT·자막·음성은 완성본에 넣지 않으며, 참고 영상에서 게임 부분만 잘라내거나 음소거해 사용하는 것도 금지한다. 독립 게임 원본의 출처와 사용 조건을 확인한 뒤 실제 장면에 맞춰 대본을 확정한다.

원본의 문제 제기·주장·사례 순서·결론을 임의로 바꾸지 않는다. 선행 개념, 작은 계산, 단계별 동작과 비교를 그 설명이 필요한 위치에 추가하고 다음 원본 대목으로 복귀한다. 개인 경험은 Sakurai의 경험으로 귀속한다. 원본 대본을 사용자가 제공하면 제공된 텍스트를 보강할 수 있으며, 제공되지 않은 전체 대본을 복제·번역하는 방식으로 만들지는 않는다. 이 구분은 설명 순서를 새로 짜라는 뜻이 아니다.

원본 게임→현재 버전 후보→동일하게 보여야 할 기능/전·행동·결과→관찰된 차이→채택/유지 이유를 같은 설계표에 기록한다. 최신 게임이라는 이유만으로 다른 메커니즘을 끼우지 않는다. 최신 출시/이용 가능 여부와 실제 소스는 선택 시 확인하고, 적합한 최신 버전이 없으면 원본을 유지한다. 추가 게임은 별도 요청이 있을 때만 넣는다. 원본 없는 강의에는 게임 수를 강제하지 않는다. 소스/권리가 부족하면 제작 전 패키지에 구체적인 문제와 대안을 적는다. 원본 미디어와 게임 녹화의 사용 조건은 별개로 확인한다.

실제 게임 대신 에이전트가 만든 게임/프로토타입/시뮬레이터를 만들지 않는다. 명시 요청한 엔진·개발 시연은 별도 자료 유형으로 사용할 수 있다. 렌더링 역사 시리즈의 엔진 데모 허용, DLSS5까지/RenderFormer·NeRF 등 제외 범위도 유지한다.

실제:설명은 보이는 화면의 역할로 분류한다. 동작 중심 게임의 보조 표식은 실제, 정지 분석·도식/숫자 비교가 중심이면 설명이며 중복 계산하지 않는다. 개론도 본편에 포함한다. 2026-10-13 사용자 지시로 총 영상 시간의 목표·최소·최대 제한과 약20분 자동 분할 규칙을 제거했다. 필요한 설명과 관련 시연에 맞춰 길이를 정하며 시간에 맞추려고 삭제·축약·패딩하지 않는다. 기존 편의 내용 범위는 유지하고, 길다는 이유만으로 추가 분할하거나 다음 편을 자동 제작하지 않는다. 실제:설명 비중과 고양이2초·회원10초 같은 개별 요소 규격은 별도로 유지한다. 예상 길이는 작업량 안내이지 제작 제한이나 승인 대기 사유가 아니다.

## 4. 전체 제작 전에 작은 샘플로 실패 방지

설계 단계에서 새 시각 체계의 대표 설명 동작과 자막/UI가 가장 까다로운 실제 게임 구간을 짧게 만든다. 상세 사람/물건, 투영·가림, 계산 단계, 움직이는 표식과 두 줄 자막을 실제 출력 크기에서 확인한다. 필요한 샘플만 만들고 이를 매 씬의 새 검수 영상으로 증식시키지 않는다. 기존의 동일 자산/서체/레이아웃 승인 근거는 재사용한다.

전체 씬의 설계표와 KO/EN 본문을 먼저 완성한다. 전체 TTS 전에 대본 연속 읽기·수치 검산·소스 용량·원문 보존·가독성 측정을 한 번 묶어 완료한다. 대표 샘플은 다른 씬의 실제 최종 픽셀 승인을 대신하지 않는다. 샘플/대본/계획의 내부 확인이 끝나면 선택한 한 편의 전체 제작을 계속한다. 이 단계에서 사용자 승인을 다시 기다리지 않는다.

강의 오디오는 사용자 승인 `lecture-lofi-game-audio-v1`을 적용한다. 내레이션 -16 LUFS, 로파이 -32~-30 LUFS(초기값 -31)를 출발점으로 삼고 중요한 게임 효과음·복잡한 계산에서는 음악을 더 낮춘다. 게임 자체 음악과 원본 해설은 로파이/내레이션과 경쟁하지 않게 조정한다. 수치는 고정 합격값이 아니며 실제 비교 샘플로 정한다. 기존 강의의 일괄 noBGM 기본값은 대체하되, 기존 납품·예약·미선택 프로젝트는 자동 변경하지 않는다. 수정할 강의는 선택한 한 편의 계획에 적용 범위를 기록한다. 곡 선택과 샘플 확인도 위 제작 전 패키지에 묶으며 별도 반복 승인 절차를 추가하지 않는다. 상세 기준은 [오디오 규격](NARRATION_AUDIO_STANDARD.md)을 따른다.

## 5. 제작 실행과 타이밍 확정

1. 현재 PID뿐 아니라 명령줄·생성시각·세션·로그로 살아 있는 작업을 확인한다. 종료된 작업을 기다리거나 새로 중복 실행하지 않는다. 무거운 TTS/합성/렌더/업로드는 한 번에 하나씩 실행한다. 승인된 현재 편만 진행한다.
2. 동일 Qwen3-TTS1.7B/레퍼런스로 장면 단위 연속 발화를 생성한다. 기존 동일 대본의 승인 PCM은 재사용한다. 발화 앞에 게임 예시 길이만큼 무음을 넣지 않는다. 연구 GPU는 현재 학습 완료/체크포인트 봉인 뒤 협력 인계하고 성공·실패 모두 자신이 정지시킨 미완료 큐만 복원·실제 재개 확인한다. 완료 연구는 재시작하지 않는다.
3. 현재 PCM의 전체 ASR을 한 번 실행해 실제 전체 문장을 대본과 직접 대조한다. 누락·반복·숫자·고유명사·임의 인사·끝소리를 확인한다. 의심 구간만 독립 완결 문맥과 실제 PCM으로 해소한다. ASR chunk 경계/역행 타임스탬프 오류를 실제 반복으로 단정하지 않는다. endingHeuristic만으로 승인하거나 예상 대본을 인식 prompt에 넣지 않는다.
4. 실측 음성으로 단일 프레임 타임라인을 확정한다. 컷·씬 시작·믹스·KOEN SRT·챕터·회원 엔딩을 함께 갱신하고 해시로 잠근다. 두 언어의 큐 수는 달라도 전체 문단 대응과 발화 경계는 일치해야 한다. 차이가 있으면 `captionAlignmentReview`의 전체 큐 매핑을 사용한다.
5. 승인 음성·음악/원음 계약으로 믹스하고 현재 최종 믹스의 전체 ASR을 한 번 직접 대조한다. unmixed 승인으로 대체하지 않는다. 동일 믹스를 또 인식하지 않는다. 음악/화자 선택 승인, 라이선스 확인, 사람 청취는 서로 별개다.
6. 씬별 실제 자막/정확 crop/현재 타이밍으로 합성 전 충돌 검사 후 clean/captioned 최종 쌍을 생성한다. 이미 승인한 씬은 재렌더하지 않는다. 프리뷰·무음 visual·prepared 상태를 최종 완료로 기록하지 않는다.

음성·레이아웃·게시 규격은 각각 [오디오](NARRATION_AUDIO_STANDARD.md), [화면](VIDEO_VISUAL_STYLE.md), [자막](CAPTION_STYLE.md), [게시](YOUTUBE_PUBLISHING.md)를 필요한 단계에서만 읽는다.

## 6. 최종 검수는 한 번, 변경에는 영향 범위만

사전 설계로 예방할 수 없는 실제 생성/인코딩 오류를 확인하는 마지막 검수는 유지한다. 한 번의 통합 검수에서 연속 설명 흐름·움직임·모든 자막/컷·음성을 함께 확인하고 같은 프레임을 여러 보고서용으로 다시 추출하지 않는다. 기술 자동 검사와 의미/픽셀 직접 검수를 구분한다.

| 확인 대상 | 완료 근거 |
|---|---|
| 내용/움직임 | 각 게임의 규칙→행동→결과→비교, 인과 연결, 상세 대상/2.5D/표식 추적·대사 동기화의 실제 재생. 정지판만으로 움직임 승인 불가 |
| 자막/컷 | 모든 큐·컷의 현재 인코딩 픽셀, 줄바꿈/박스/그림자/UI/수식/회원 이름 여백. 같은 프레임이 여러 검사를 충족하면 한 번만 확인하고 범위 매핑 |
| 기술 | 두 최종 MP4 전체 decode, 실측 프레임/PTS/길이/해상도/fps, 끊김·빈/중복 구간, 본편 비중, 동일 AAC, LUFS/true peak. 새 출력은 해당 파일의 검사 필요 |
| 음성 | 현 PCM/최종 믹스 ASR 전체 직접 대조와 해결된 의심 구간. 실제 사람이 듣지 않았다면 전체 청취·발음은 pending |
| 납품 | `node scripts/collect-video-output.cjs <slug>`의 clean/captioned/KO/EN4파일과 output index, 현재 해시·자막 대응. 수집이 게시 승인인 것은 아님 |
| 플랫폼 | 승인된 업로드의 실제 ID·파일·비공개/예약 상태·SD/HD·CCoff게임/설명 자막·수동KOEN·영어정보·썸네일·카드·엔딩·광고/저작권 상태 저장 후 재열람 |

검사 결과는 `pass / fail / pending / reused`와 실제 입력 해시/구간으로 기록한다. 기준을 충족하지 않은 항목에 pass를 쓰지 않는다. 샘플 검수는 실제 범위를 적고 전체 확인으로 부풀리지 않는다.

### 재사용·재검수 기준

| 변경 | 다시 할 일 | 유지할 일 |
|---|---|---|
| 제목·설명·문서만 | 해당 텍스트/링크·플랫폼 저장 검증 | 영상·TTS·ASR·자막 픽셀 |
| 썸네일만 | 해당 이미지/작은 크기·실제 저장 | 영상 전체 |
| 시각 요소/crop만, 시간 동일 | 바뀐 구간과 접합부의 동작/자막/UI, 새 출력 기술검사 | PCM·ASR·타이밍; 동일 관련 입력/decoded pixels 근거가 있는 기존 검수 |
| 자막만 | 변경 큐/인접 경계 픽셀·새 captioned 기술검사 | clean·PCM·믹스 |
| 음량/음악만 | 믹스·현재 믹스 ASR·음량·새 출력 기술검사 | 변경 없는 화면/대본/TTS/타이밍 |
| 일부 대사/길이 | 해당 TTS와 문맥, 영향받는 타이밍·믹스·자막·컷·챕터·엔딩·새 출력 검사 | 영향 없는 승인 PCM/소스/씬 |
| 공통 폰트/템플릿 | 실제 영향을 받는 전체 씬/큐 | 무관한 프로젝트·음성 |

같은 해시라도 시간·crop·자막·필터·렌더러/폰트가 바뀌면 관련 검수는 재사용하지 않는다. 새 인코딩은 파일의 전체 decode/PTS/오디오 무결성을 확인하되, 그 때문에 동일 장면의 개념 검토·전체 TTS·소스 확보를 반복하지 않는다. 실패는 원인·수정·영향 범위를 한곳에 적고 그 범위만 수리한다. 로그 정리, 새 턴, 토큰 부족, 날짜 변경은 미디어 재생성 사유가 아니다.

## 7. 기존 영상 검토와 수리

검수만 요청된 기존 영상은 현재 Studio/manifest/receipt와 실제 내용으로 **유지할 부분 / 근거 있는 문제 / 필요한 수정 / 예상 영향**을 보고한다. 제작·수정까지 지시된 한 편은 해당 범위의 수리와 자체 검수를 거쳐 비공개 업로드까지 자율적으로 완료한다. 이미 충족한 부분은 재제작하지 않고 미선택 영상은 건드리지 않는다.

수정 시 유용한 기존 설명·순서·승인PCM·회원 신원·원래 팔레트와 역사 납품을 보존한다. 바뀐 부분의 시각/음성 승인만 무효화한다. 교체 업로드·예약 이동·옛 영상 삭제는 승인된 정확한 ID/범위와 검수 완료 교체본이 있어야 하며, 원본을 먼저 지우지 않는다. 앞선 Game Math Part2의 `game-math-normal-transform-uv`까지라는 경계는 상한이며, 여섯 Sakurai 새 영상이나 다음 강의의 착수 허가가 아니다.

## 8. 게시·Git·종료

선택한 한 편은 검수한 captioned 파일을 한 번 비공개 업로드하고 가능한 게시 설정까지 저장·재열람한다. 이 비공개 업로드에는 중간 승인을 다시 요청하지 않는다. 별도 승인된 예약에는 매일 디자인/강의 교대09:00 Asia/Seoul 형식을 참고하되 실제 Studio/기존 날짜/시리즈 순서가 우선한다. 기존 예약 자체는 변경하지 않는다. 자세한 저장 항목은 [게시 규격](YOUTUBE_PUBLISHING.md)을 따른다.

플랫폼 한도/선택형CC 전파/비공개댓글은 실제 후속으로 남긴다. 가능한 현재 편의 작업과 Git 전달은 끝내되 다음 편을 자동 시작하지 않는다. 실제 저장 전 썸네일/fullSettings는 false다. 댓글 원문 준비는 게시·고정 완료가 아니다. 사람 청취·발음·공개 권리·외부 백업 미완료도 그대로 보고한다.

완료된 승인 작업은 [미디어/Git 규격](MEDIA_STORAGE.md)에 따라 선택 커밋·일반 푸시한다. 현재 HEAD의 임시 index/명시 경로/최종 blob/외부 index 동일/실제 원격 SHA를 확인한다. 비디오·오디오·압축·원본info·QA 래스터는 Git 제외, 필수 이미지에만 exactpath/목적/이유/SHA/ignore 예외를 둔다. 완료 Git을 기록하기 위한 무한 후속 커밋은 만들지 않는다.

최종 보고는 그 편의 결과 링크, 완료 단계, 실제 남은 항목, 사용자 다음 확인 한 가지로 끝낸다. 준비·실행 중·기술완료·비공개저장·게시설정완료·사람검토완료를 구별한다. 다음 편은 사용자가 선택할 때만 시작한다.
