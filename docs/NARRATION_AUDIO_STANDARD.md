# 내레이션·자막·오디오 제작 기준

이 문서는 이 저장소에서 새 영상을 만들 때 적용하는 기본 오디오 규칙입니다.
프로젝트별 예외가 필요하면 `projects/<slug>/README.md`와 `project.json`에 이유를
기록합니다. 기존 완성작은 보존하고, 새 프로젝트에는 이 기준을 적용합니다.

2026-09-06 FPS 영상에서 사용자가 승인한 믹스를 기본값으로 채택했습니다.
기존의 더 작은 배경음 기준은 아래 값으로 대체합니다. 배경음을 키우는 요청에서는
승인된 내레이션의 목소리·속도·음량을 유지하고 게임 원음과 BGM만 조정합니다.
이후 같은 날의 추가 요청에 따라 BGM을 설명 구간에만 넣던 방식은 폐기하고,
**영상 처음부터 끝까지 연속 BGM + 게임 구간 원음 동시 재생**을 기본으로 합니다.

## 승인 순서

다음 단계를 건너뛰지 않습니다.

1. 장면별 한국어 대본을 검토하고 확정한다.
2. 짧은 TTS 비교 샘플로 목소리·속도·톤을 승인받는다.
3. 전체 TTS, 한국어 SRT와 타이밍 JSON을 생성한다.
4. 전체 음성을 다시 받아써 누락·반복·고유명사 오류를 검토한다.
5. 한국어 타이밍을 유지한 번역 SRT를 생성한다.
6. 사용할 BGM 후보와 라이선스를 먼저 제시하고 명시적으로 선택받는다.
7. 선택 전에는 BGM을 다운로드하거나 최종 영상에 섞지 않는다.
8. 화면 타이밍을 확정하고 게임 원음과 승인된 BGM을 믹스한다.
9. 최종 MP4와 Motion Canvas 편집기에 같은 전체 믹스를 연결한다.
10. 최종 음량, 장면별 배경음, 편집기 재생, 자막 종료 시간과 영상 길이를 검사한다.

## 기본 TTS 설정

- 모델: `Qwen3-TTS-12Hz-1.7B-Base`
- 언어: 한국어
- 기준 음성: `shared/voice-reference/reference-15-35s.wav`
- 기준 발화문: `shared/voice-reference/reference-15-35s.ko.txt`
- 합성 단위: 문장별이 아닌 **장면별 연속 발화**
- SRT 단위: `narration.ko.json`의 각 `lines` 항목
- 장면 사이 기본 휴지: 0.72초
- 출력 버전: 새 프로젝트는 `qwen3-1.7b-balanced-v1`에서 시작하고, 승인된
  음성을 다시 만들 때는 기존 결과를 덮지 말고 `v2`, `v3`로 올린다.

기준 음성과 발화문은 같은 구간이어야 합니다. 기준 음성은 개인 정보이므로 Git에
올리지 않으며, 렌더된 프로젝트 음성만 필요에 따라 공유합니다.

기준 발화문이 없거나 기준 음성을 바꿨다면 먼저 실행합니다.

```powershell
qwen3-tts/.venv/Scripts/python.exe qwen3-tts/transcribe_reference.py `
  shared/voice-reference/reference-15-35s.wav `
  --output shared/voice-reference/reference-15-35s.ko.txt
```

`ref_text`를 포함한 음성 복제 모드를 사용합니다. 발화문 없이 화자 벡터만 사용하는
모드는 빠른 임시 샘플 외에는 기본 제작 방식으로 사용하지 않습니다.

## TTS 미리듣기와 전체 내레이션 생성

전체 생성 전에 첫 장면 또는 대표 장면으로 미리듣기를 만듭니다.

```powershell
qwen3-tts/.venv/Scripts/python.exe qwen3-tts/generate_sample.py `
  --project <slug> --scene 01
```

기본 출력은 `shared/audio-samples/<slug>-qwen3-1.7b-approval-sample.wav`입니다.
대본과 샘플이 승인된 뒤 저장소 루트에서 전체 패키지를 생성합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File scripts/build-project-narration.ps1 -Project <slug>
```

이 명령은 다음 작업을 순서대로 수행합니다.

1. 장면 단위 TTS와 한국어 SRT·timing JSON 생성
2. 영어 대본이 있으면 같은 타이밍의 영어 SRT 생성
3. Motion Canvas용 장면 타이밍과 `assets/narration.wav` 동기화
4. Whisper 전체 받아쓰기 파일 생성

생성 중 중단돼도 품질 검사를 통과한 장면 WAV는 재사용합니다. 한 장면의 출력이
비정상적으로 길어지는 것을 막기 위해 최대 출력 토큰을 제한합니다.

`chunks/`와 `preview-*` 파일은 다시 만들 수 있는 중간 결과라 Git에 올리지 않습니다.
공유하거나 보관할 결과는 최종 WAV, 한국어·영어 SRT, timing JSON과
`*.asr-review.txt`입니다.

## TTS 품질 기준

- 같은 장면의 문장은 한 번에 읽혀야 한다.
- `~합니다`, `~했습니다`, `~됩니다` 같은 종결 어미가 잘리지 않아야 한다.
- 끝부분 음량과 감쇠 시간을 검사하고 기준 미달 결과는 최대 3번 다시 생성한다.
- 매우 조용하게 닫힌 발음은 끝 단어가 온전히 인식되는지 받아쓰기로 재확인한다.
- 전체 받아쓰기에서 문장 누락, 반복, 숫자와 고유명사 오류를 확인한다.
- SRT 수는 모든 장면의 `lines` 수와 같아야 한다.
- SRT는 겹치거나 역전되지 않아야 하며 마지막 자막은 음성 길이를 넘지 않는다.
- 새 타이밍으로 Motion Canvas를 빌드해 모든 장면이 독립적으로 연결되는지 확인한다.

받아쓰기 결과는 자동 합격 판정이 아니라 검토 자료입니다. 숫자 표기처럼 Whisper가
정규화하는 차이는 허용하지만, 내용이 달라졌다면 해당 장면만 다시 생성합니다.

## 실제 게임 영상과 채널 그래픽

기본 구성은 한 장면 안에서 다음 페어를 사용합니다.

1. 실제 게임·공식 기술 예시 영상 1개: 보통 5~10초
2. 같은 개념을 설명하는 자체 Motion Canvas 또는 Manim 화면 1개

한 화면에는 핵심 개념 하나만 보여 줍니다. 원본 영상의 고유 편집이나 자막 구성을
복제하지 않고, 필요한 동작만 짧게 인용한 뒤 자체 설명 화면으로 전환합니다.

게임 영상은 영상 스트림만 추출하지 않습니다. 유용한 효과음과 환경음은 보존하되,
원본 음악이 권리 문제를 일으킬 수 있으면 효과음 중심 구간을 고르거나 해당 음악만
낮추거나 제거합니다. 원본 링크, 권리자, 사용 구간, 화면과 소리의 사용 근거를
`sources/SOURCES.md`에 기록합니다.

## 음악 선택 승인

잔잔한 BGM 한 곡을 영상 처음부터 끝까지 연속으로 사용합니다. 실제 게임 원음이
나오는 동안에도 끊지 않고 함께 재생하며, 원음과 경쟁하지 않게 음량만 조절합니다.

최종 믹스 전에 최소한 다음 정보를 포함한 후보를 제시합니다.

| 항목 | 기록 내용 |
| --- | --- |
| 곡명·아티스트 | 정확한 표기 |
| 미리듣기·원본 링크 | 권리자가 제공한 페이지 우선 |
| 라이선스 | YouTube Audio Library, CC BY 4.0 등 |
| 출처 표기 | 필요 여부와 붙여 넣을 정확한 문구 |
| 사용 범위 | YouTube 전용인지 다른 플랫폼도 가능한지 |
| 영상 적합성 | 톤, 악기, 내레이션 방해 정도 |

YouTube 게시만 고려하면 YouTube Studio 오디오 보관함의 `저작자 표시 필요 없음`
필터를 우선합니다. 외부 라이브러리 곡은 ‘무료’라는 설명만 믿지 말고 원본
라이선스 페이지를 확인합니다. CC BY 곡을 선택하면 설명란에 출처를 반드시 넣습니다.

## 기본 믹스 기준

아래 값은 승인된 시작점이며 실제 청취 결과에 따라 조정합니다. LUFS는 각 레이어의
정규화 목표이고, 최종 출력 측정값이나 고정된 볼륨 퍼센트가 아닙니다.

| 항목 | 기본값 | 적용 기준 |
| --- | --- | --- |
| 내레이션 | -16 LUFS | 중심 트랙, 승인된 목소리·속도·음량 유지 |
| 게임·기술 영상 원음 | -23 LUFS | 실제 예시 구간, 덕킹 전 목표 |
| 연속 BGM | -28 LUFS | 전체 타임라인, 덕킹·겹침 감쇠 전 목표 |
| 게임 원음과 겹치는 BGM | 추가 -3dB | 원음이 재생될 때만 완만하게 낮추고 끄지 않음 |
| 사이드체인 덕킹 | threshold 0.08, ratio 2.2 | attack 15ms, release 280ms, makeup 1 |
| 덕킹 감소량 | 약 3dB를 의도 | 내레이션 크기에 따라 달라지며 고정 감쇠가 아님 |
| BGM 페이드 | 인·아웃 각각 0.45초 | 영상 맨 처음·맨 끝에만 적용; 씬 경계에서 끊지 않음 |
| BGM 반복 연결 | 1초 크로스페이드 | 곡이 영상보다 짧을 때 끝과 다음 시작을 겹쳐 연결 |
| 게임 원음 페이드 | 인 0.12초, 아웃 0.3초 | 장면 전환의 클릭·급격한 끊김 방지 |
| 최종 출력 | AAC 192kbps, 48kHz, 스테레오 | 인코딩 후 true peak -1.5 dBTP 이하 확인 |

설명용 상대 음량은 덕킹 후 게임 원음이 내레이션보다 약 10dB, BGM은 약 15dB
작은 정도를 의도합니다. `gameAudioUnderNarrationDb`, `bgmUnderNarrationDb`,
`duckingDb`는 이 의도의 기록이며, 현재 믹서가 실제 사용하는 값은
`gameAudioTargetLufs`, `bgmTargetLufs`, `duckingThreshold`, `duckingRatio`입니다.
상대 음량 필드만 바꾸고 소리가 바뀌었다고 판단하지 않습니다.

`audio.bgmPlacement`는 `continuous`, `bgmDuringGameplayDb`는 `-3`,
`bgmLoopCrossfadeSeconds`는 `1`로 기록합니다. 게임 원음이 시작·종료될 때
0.45초에 걸쳐 BGM 음량만 부드럽게 조절합니다. 게임 구간에도 내레이션·게임 원음·
BGM이 함께 존재하고, 설명 구간에는 내레이션·BGM이 이어집니다.

원음 트랙이 없거나 사실상 무음이면 해당 씬을 `audio.musicFallbackScenes`에
기록합니다. 그 씬에는 원음을 추가하지 않고 이미 흐르는 BGM을 유지하며,
원음 겹침용 -3dB 감쇠도 적용하지 않습니다. 씬마다 곡을 처음부터 다시 시작하지 않습니다.

게임 예시 구간에는 작은 원음과 승인된 BGM이 함께 있어야 하고, 자체 설명 구간에도
동일한 BGM이 계속 있어야 합니다. 단, 침묵이 연출상 필요한 장면은 프로젝트 문서에
의도를 기록합니다.

## 편집기와 최종 MP4의 오디오 일치

내레이션 원본과 전체 믹스는 별도 파일로 보관합니다.

- `paths.narration`: 원본 TTS WAV. 재믹스의 입력이며 덮어쓰지 않습니다.
- `paths.audioMix`: `motion-canvas/src/projects/<slug>/assets/final-mix.m4a`.
  내레이션·게임 원음·BGM이 모두 포함된 편집기용 마스터입니다.
- `paths.videoClean`: 위 전체 믹스가 포함된 최종 무자막 MP4입니다.
- `paths.audioReport`: `projects/<slug>/audio/mix-report.md`. 설정, 측정값,
  원음 대체 씬과 청취 검수 결과를 기록합니다.

새 프로젝트의 무음 플레이스홀더와 TTS 전용 `assets/narration.wav` 연결은
기획·음성 검토 단계에서만 사용합니다. 믹스 파일이 생성된 뒤 `project.ts`를
아래처럼 전환해야 하며, MP4만 믹스하고 편집기를 내레이션 전용으로 남겨 두지 않습니다.

```ts
import finalMix from './assets/final-mix.m4a';
// makeProject의 기존 name, scenes 등은 유지합니다.
// audio: finalMix,
```

1. 재믹스는 원본 TTS, 원음 클립, 승인된 음악에서 시작합니다. 이미 믹스된 MP4의
   오디오를 다시 입력해 같은 배경음을 두 번 더하지 않습니다.
2. 지연된 배경 트랙을 합치는 `amix`에는 `normalize=0`을 명시합니다.
   기본 정규화가 아직 재생되지 않는 트랙까지 세어 배경음을 과하게 줄일 수 있습니다.
   내레이션과 배경의 최종 합산도 `normalize=0`으로 하고 피크를 별도 검사합니다.
3. 타임라인은 실제 `timing.ts`와 같은 씬 경계·반올림 규칙을 사용합니다.
   음량만 수정할 때는 화면 스트림, 전체 길이, 한국어·영어 SRT를 유지합니다.
4. 임시 MP4를 만들고 스트림·길이를 검증한 다음 최종 파일을 교체합니다.
   MP4의 AAC를 `-c:a copy`로 추출한 M4A를 편집기에 연결하면 추가 손실 없이
   동일한 믹스를 사용할 수 있습니다.
5. 전체 믹스에 원음이 들어 있으므로 편집기의 개별 HTML Video 요소만 음소거합니다.
   원본 클립에서 오디오를 삭제하지 않습니다. 씬이 끝나면 Video 재생도 중지합니다.
6. 음성·음악·클립·타이밍 변경 후에는 MP4와 M4A를 함께 갱신합니다.
   편집기는 새로고침하고, 소리가 안 나면 스피커 음소거 상태부터 확인합니다.

현재 구현 예시는 `scripts/mix-frame-rate-audio.ps1`과 FPS 프로젝트의
`scenes/broll.tsx`입니다. 이 믹서는 **20개 씬·각 6.5초 예시 구간**을 전제로 합니다.
새 영상에 재사용할 때 씬 수·예시 길이·클립 경로를 해당 타임라인에 맞춰 조정해야
하며, `-Project` 이름만 바꾸는 범용 믹서로 취급하지 않습니다.

FPS 영상 재믹스 및 배경 단독 검수 파일 생성:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/mix-frame-rate-audio.ps1 `
  -Project frame-rate-modern-rendering -ExportBackgroundReview
```

기존 승인곡은 `Nimbus — Eveningland`이며
`shared/assets/music/youtube-audio-library/Nimbus-Eveningland.mp3`에 있습니다.
새 영상의 곡 선택·출처 기록은 별도로 유지하고, 이 문서가 모든 곡의 자동 승인을
의미하지는 않습니다.

## 배경음 누락·중복 방지 검수

- 전체 믹스의 LUFS·true peak와 배경 단독 트랙을 각각 검사합니다. 전체 음량이
  정상이어도 내레이션만 들어 있을 수 있으므로 AAC 존재만으로 완료하지 않습니다.
- 모든 씬에서 게임 구간과 설명 구간을 따로 표본 측정하고 청취합니다. 초반·중반·
  후반의 배경음이 의도 없이 작아지거나, 전환에서 겹치거나 빠지지 않아야 합니다.
- `-ExportBackgroundReview`는 `background-only.wav` 외에
  `bgm-only-before-narration-ducking.wav`도 생성합니다. 후자는 원음 겹침 감쇠를
  포함하되 내레이션 덕킹 전의 BGM 단독 트랙입니다. 게임·설명 전환과 곡 반복
  지점에서 음악이 계속 있는지 별도로 확인합니다.
- 원음 대체 목록은 프로젝트마다 새로 판단합니다. FPS 07번 예외를 무조건 복사하지 않습니다.
- 편집기에서 `audio`가 `final-mix.m4a`를 가리키고 실제 재생 시간이 증가하는지,
  개별 Video가 음소거되어 이중 재생되지 않는지 확인합니다.
- Render의 `include audio`를 켜고 MP4와 편집기 믹스의 길이를 확인합니다.
  AAC 패킷 복사 직후에는 두 파일의 오디오 패킷 해시도 같아야 합니다.
  별도로 재인코딩한 출력은 패킷 해시 대신 동기화·내용·음량을 비교합니다.
- 편집기가 이미 열려 있다면 `Ctrl+F5`로 갱신하고, 스피커가 꺼져 있으면 `M`으로
  음소거를 해제한 뒤 `Space`로 재생합니다.

## 최종 출력과 완료 조건

- 기본 게시본: 1920×1080, 60fps, H.264 + AAC
- 유튜브 본편: 고정 자막 없는 영상과 한국어·영어 SRT를 별도 제공
- 쇼츠나 SNS용으로 필요할 때만 고정 자막 버전을 추가 생성
- `project.json`의 음악 승인 상태와 최종 파일 경로를 갱신
- 내레이션 WAV와 전체 믹스 M4A를 구분해 보관하고 편집기·MP4의 소리를 함께 검수
- `scripts/check-video-project.ps1 -Project <slug> -Stage publish` 통과
- 사람이 처음부터 끝까지 듣고 승인한 뒤에만 상태를 `complete`로 변경
