# 내레이션·믹스 기술 규격

승인 시점과 검사 횟수/재사용은 [통합 제작 규칙](VIDEO_WORKFLOW.md)을 따른다. 기존 승인 음성·음악은 재사용하고 변경할 때만 새 비교 샘플/선택이 필요하다. 사람 전체 청취·발음과 기술 QA 상태는 분리한다.

## TTS와 발화 설계

- 모델 `Qwen3-TTS-12Hz-1.7B-Base`, 한국어, `shared/voice-reference/reference-15-35s.wav`와 동일 구간의 `.ko.txt`를 `ref_text`로 사용한다. 기준 음성은 개인 자료이며 Git 제외다.
- 장면 단위 연속 발화, 기본 scene gap0.72초, `qwen3-1.7b-balanced-v1`. 실제 대본/승인된 프로젝트 예외를 따른다. 문장마다 합성하거나 자료화면 앞에 무음 슬롯을 붙이지 않는다.
- 전체 생성 전에 숫자·약어·외래어·수학 기호의 발화형과 화면 표기형을 정리한다. 새로운 화자/설정이면 짧은 샘플로 확인하고, 동일 승인 설정에는 승인을 반복 요청하지 않는다.
- `scripts/build-project-narration.ps1 -Project <slug>` 등 현재 프로젝트의 검증된 실행기를 사용한다. 역사 버전의 실행기를 모두 돌리지 않는다. 기존 승인 PCM을 덮지 않고 변경 대목만 합성한다. 실패 재시도는 실제 원인을 확인해 해당 장면만 최대3회; 계속 실패하면 이유를 보고한다.
- TTS 후 현재 WAV의 전체 ASR을 한 번 대조한다. 누락·반복·숫자·이름·임의 인사·조사·끝음절을 본다. 모호한 부분에만 독립 완결 문맥과 PCM을 추가 확인한다. 무음/0초 타임스탬프/chunk 경계 인식 오류만 보고 원음 잘라내기 금지. 종료 감쇠 heuristic은 보조 지표이며 승인 근거를 대체하지 않는다.
- 최종 믹스는 현재 믹스의 전체 ASR을 별도로 한 번 검토한다. 기존 unmixed 결과로 대체하지 않으며 같은 해시의 성공 검사를 반복하지 않는다. 실제 사람이 듣지 않은 음성을 청취 완료라고 기록하지 않는다.

## GPU 인계

새 작업 전 실제 GPU/프로세스 명령줄·생성시각·큐 상태를 확인한다. 현재 연구 학습의 완료·최종 체크포인트·validation/done marker를 기다려 작업 경계에서 협력 정지하고 단일 TTS 배치를 실행한다. 강제 종료·VRAM 보유 suspend·adapter만으로 optimizer/RNG 재개 주장 금지.

원래 명령/cwd/큐/완료표식/소유 정지 토큰을 기록한다. 성공·실패 모두 자신이 정지시킨 미완료 큐를 복원하고 실제 새 작업 상태를 확인한다. 다른 사용자의 hold를 지우거나 이미 완료된 연구를 재시작하지 않는다. 구현 참조 `production/batches/game-math-part2-full-series/gpu-handoff.py`; 실제 상태 `shared/output/GPU_HANDOFF.json`. 이 구현을 다른 연구에 쓰기 전에 실제 정지/재개 인터페이스를 확인한다. 안정적인 자원 확보 실패는 대기/실패이며 연구가 돌아간다고 추정하지 않는다.

## 타이밍과 언어

실측 PCM과 단일 프레임 타임라인을 씬/믹스/KOEN/챕터/엔딩의 기준으로 쓴다. 각 문단을 보존하고 SRT 겹침·역전·끝초과를 금지한다. 한영 큐 수/절 길이가 다를 때 `project.json.paths.captionAlignmentReview`에 현재 두 파일 SHA·모든 큐를 순서대로 한 번씩 포함한 문단 매핑·경계를 기록한다. 동일 큐 수를 맞추려고 의미를 삭제하지 않는다.

## 음악·원음 계약

음악 선택과 실제 파일·권리 확인은 다르다. `Nimbus — Eveningland`의 기존 선택은 재사용하되 실제 사용 파일과 라이선스 미확인을 승인으로 바꾸지 않는다. 선택한 한 편의 자동 완료 범위 안에서 새 곡이 필요하면 승인된 음악 스타일에 맞춰 곡명/아티스트/원본/사용 범위/표시 조건과 샘플 적합성을 내부 확인해 선택한다. 같은 단계의 사용자 승인을 다시 요구하지 않으며 완료 후 검수에서 조정할 수 있다. 표시 필수인 자료는 출처 블록 생략 정책을 이유로 조건을 무시하지 않고 조건을 충족하거나 다른 자료를 선택한다.

강의 기본값은 사용자 승인(2026-10-13, 낮은 로파이와 게임 사운드 유지 제안에 “응”)에 따라 `lecture-lofi-game-audio-v1`이다. 보컬 없이 멜로디·드럼·잡음이 과하지 않은 로파이를 낮게 깔고 내레이션을 가장 선명하게 유지한다. 이는 기존 강의의 일괄 noBGM 기본값을 대체한다. 기존 납품/예약/미선택 프로젝트는 자동 재믹스하지 않으며, 사용자가 고른 강의의 계획에 이 변경을 반영한다. 이후 해당 편에 명시한 무BGM 예외가 있으면 그 범위에 따른다. 게임 디자인 영상의 승인 Nimbus 계약은 이 강의 변경으로 바꾸지 않는다.

설명 구간과 게임 구간이 들어간30–60초 샘플로 기존/제안 믹스를 비교하고 곡·음량을 제작 전 패키지 안에서 확정한다. 기존 승인 PCM을 사용하고 새 원고라면 필요한 짧은 샘플만 만든다. 같은 곡/설정의 승인 근거는 재사용한다. 현재 승인은 음악 스타일/운영 원칙이며 개별 곡 선택·라이선스·실제 샘플 청취 완료를 뜻하지 않는다.

게임 효과음·환경음은 원래 동작과 동기화해 유지하고, 중요한 조작/타격/UI 소리가 나올 때와 복잡한 계산·핵심 설명 중에는 로파이를 더 낮춘다. 게임 자체 BGM·원본 해설은 경쟁하지 않게 제외/조정한다. 영상 전용 원본이나 원음이 섞여 분리할 수 없는 자료는 보존된 오디오/적절한 원본을 먼저 확인하고 제한을 기록한다. 없는 효과음을 임의로 만들어 원음 보존이라고 하지 않는다. 원본 파일은 보존한다.

로파이는 [YouTube 오디오 보관함](https://support.google.com/youtube/answer/3376882?hl=ko)을 우선 검토한다. 곡마다 실제 다운로드 출처·허용 사용 범위·수익화·저작자 표시 조건을 기록하며, “저작권 없음”이라는 제목만으로 승인하지 않는다. 필요한 출처 문구는 게시 설명에 포함한다.

| 항목 | 기본 시작값 |
|---|---|
| 내레이션 / 게임 원음 | -16 / -23 LUFS; 설명 명료성과 실제 효과음에 맞춰 조정 |
| 강의 로파이 | -32~-30 LUFS 범위에서 시작, 초기 작업값 -31; 비교 샘플로 확정 |
| 그 밖의 기존 승인 BGM | 해당 계약 유지; 일반 시작값 -28 LUFS |
| BGM 배치 | 처음부터 엔딩까지 연속; 씬마다 재시작 금지 |
| 원음과 겹칠 때 BGM | 추가 -3dB에서 시작, 약0.45초 완만한 전환; 중요한 효과음/핵심 설명은 필요에 따라 더 낮춤 |
| 덕킹 | threshold0.08, ratio2.2, attack15ms, release280ms, makeup1 |
| BGM 페이드 | 전체 맨 앞/끝0.45초 |
| 곡 반복 | 1초 크로스페이드 |
| 원음 페이드 | 시작0.12초/끝0.3초 |
| 최종 AAC | 192kbps,48kHz,stereo; 인코딩 후 true peak ≤ -1.5dBTP |

위 LUFS는 레이어 정규화 시작값이며 합산 최종 측정값과 구별한다. 프로젝트 준비 시 강의 템플릿의 `audio.lectureDefaults`를 실제 `audio.bgmTargetLufs` 등 현재 믹서 입력 필드로 명시적으로 반영한다. `lectureDefaults`는 설정 안내이며 구형 믹서가 자동 적용한다고 가정하지 않는다. 실제 출력과 샘플 확인으로 최종 값을 기록한다. 배경 합산 `amix normalize=0`; 배경 트랙 중복/누락·클리핑·급변을 검사한다. 원음 없는 씬은 musicFallbackScenes에 기록하고 선택한 승인 BGM을 연속 유지한다.

`paths.narration`은 원본 TTS, `paths.audioMix`는 전체 믹스다. 편집기 `audio`도 전체 믹스에 연결하고 개별 Video 재생만 mute해 이중 재생을 막는다. 최종 MP4에서 AAC packet-copy한 M4A와 동일 해시를 사용한다. 편집기 AAC 미지원이면 같은 믹스의 PCM/MP3를 `paths.editorAudioMix`에 연결한다. 음성만 든 임시 WAV/무음 placeholder는 완성본이 아니다.

음량만 바꾸면 승인 TTS/타이밍/자막/화면을 보존하고 믹스·인코딩·현재 믹스 검사만 갱신한다. 시각만 바꾸면 음성을 재생성하지 않는다. 믹스의 ASR·음량·배경 레이어 검사를 통합하여 중복 실행하지 않는다. 최종 clean/captioned는 동일 믹스·길이와 AAC를 사용한다. 전체10초 엔딩까지 믹스를 연장하며 발화 없는 회원 화면에는 SRT를 만들지 않는다.

## 내레이션 음량 급락 예방과 검수

사용자 요청(2026-10-14)에 따른 `narration-level-continuity-v1`. 문장 중간이나 장면 전환에서 목소리가 갑자기 작아지는 현상도 필수 검수 대상이다. 전체 평균 LUFS·true peak가 맞거나 ASR이 문장을 인식해도 국소 음량의 안정성을 입증하지 못한다. 아래 수치는 이 저장소의 **의심 구간을 찾는 시작 기준**이며 방송 표준이나 자동 불합격/자동 보정 기준이 아니다.

### 제작 전에 예방

- 같은 화자의 씬·문단은 승인된 발화 음량을 기준으로 맞춘다. 무음 길이가 다른 파일의 전체 RMS만 비교하지 않고 실제 발화 구간을 비교한다. 기존 승인 PCM은 보존하고 필요하면 편집용 복사본에 일정한 클립 게인이나 완만한 구간 보정을 적용한다. 자연스러운 강세·문장 끝소리를 모두 같은 크기로 평탄화하지 않는다.
- 내레이션을 사이드체인의 기준 신호로 삼고, 덕킹 대상은 게임 원음/BGM이다. 게임 소리가 시작됐다는 이유로 목소리가 내려가지 않게 실제 필터 연결을 확인한다. `amix normalize=0` 등 합산 설정을 명시하고 입력 수·트랙 시작/종료에 따른 의도하지 않은 게인 변화, 중복 정규화, 자동 게인, 강한 리미터의 감쇠/회복도 확인한다.
- 페이드·크로스페이드·클립 경계가 단어 또는 문장 끝을 침범하지 않도록 현재 PCM의 발화 경계로 배치한다. 의도적으로 작은 대사는 미리 해당 범위와 이유를 적는다. 검출 뒤 이유 없이 예외로 바꾸지 않는다.
- 기존30–60초 대표 샘플에 보통 설명·강한 게임 효과음·음악 진입/종료·씬 또는 문단 접합을 가능한 한 포함해 **같은 재생 볼륨**으로 비교한다. 샘플과 설정이 동일하면 재사용하며 별도 사용자 승인 단계나 검수용 파일 묶음을 늘리지 않는다.

### 기존 음성·믹스 검수에 통합

1. 원본 PCM → 실제 게인/페이드/덕킹을 적용한 내레이션 단독 트랙 → 최종 MP4에서 디코딩한 오디오를 동일 타임라인으로 대응시킨다. 믹스 출력으로 내레이션이 분리되지 않으면 현재 필터와 같은 처리를 거친 단독 트랙을 내부 진단에 사용한다. 배경음이 전체 에너지를 채울 수 있으므로 혼합 오디오의 RMS만으로 목소리 정상 판정을 하지 않는다. 실제 파일·필터/설정·배치 시간의 해시를 기록한다.
2. 전체 발화 구간을 한 번 훑어 국소 RMS(dBFS)를 기본400ms 창/100ms 간격으로 측정하고, 같은 방식의 인접 발화 수준과 비교한다. 현재 PCM·단어/문단 경계·파형을 함께 써서 의도된 무음, 호흡, 자연스러운 끝 감쇠를 구별한다. 낮은 레벨이라는 이유만으로 약해진 음절을 무음으로 제외하지 않는다. 3초 short-term LUFS를 함께 쓰면 RMS와 단위를 구별해 기록한다.
3. 우선 검토할 구간은 **비슷한 인접 발화보다6dB 이상 낮은 상태가0.5초 이상 이어지는 곳**, **연속 문단/씬의 발화 수준이3dB 이상 바뀌는 접합**, 그리고 수치와 관계없이 들리는 급락·펌핑·끊긴 끝소리다. 비교 기준은 해당 씬/앞뒤 발화로 잡고 기준 구간과 측정 방법을 적는다. 길이가 짧거나 발화 비교가 부적절하면 수치로 단정하지 않고 문맥을 확인한다. 씬 경계·게임/BGM 시작/종료·페이드·자동 게인/덕킹 변경 지점을 우선 대조한다.
4. 의심 구간의 앞뒤2–3초 또는 완결 문장까지 이어서 원본/내레이션 트랙/최종 믹스를 동일 볼륨으로 비교 재생·청취한다. 원본부터 약한지, 편집 게인·페이드·트랙 합산/리미터에서 약해졌는지, 실제 목소리 레벨은 유지되지만 배경에 가려지는지 구분한다. 정당한 억양/무음 예외도 실제 근거와 범위를 남긴다. 측정/ASR만 수행했다면 청취로 기록하지 않으며, 해소되지 않은 의심 구간은 `pending` 또는 `fail`로 남긴다.
5. 편집·믹스 문제면 게인/페이드/배경/필터 연결을 해당 범위만 수정한다. 원본 합성 자체의 결함이 확인되고 믹스로 해결할 수 없을 때만 해당 TTS를 재생성한다. 수정 구간과 양쪽 접합을 전후 비교하고 새 최종 출력의 decode/PTS/음량·피크/오디오 무결성은 확인한다. 동일 PCM/필터/타이밍의 성공 분석은 재사용하고, 변경된 믹스의 ASR은 기존 규칙대로 한 번만 실행한다.

기존 `audio/mix-report.md`와 `production/review-ledger.json`에 `narration-level-continuity` 항목으로 입력 해시, 검사 범위, 측정 창/비교 기준, 의심 시각·차이·지속시간, 원인/예외, 수정 전후 결과, 실제 청취 주체/범위, 남은 문제를 연결한다. 미해결 급락을 남긴 채 해당 항목을 통과로 쓰지 않는다. 특정 구간의 기술 검수·청취와 사람이 전편을 들은 상태는 별개이며 전편 청취/발음은 실제 수행 전까지 pending이다. 이 항목은 내부 제작/최종 검수에 합치며 기존 납품의 자동 재믹스나 새 자동 작업을 시작하지 않는다. 문서·템플릿 추가만으로 기존 검사기에 자동 검출 기능이 생겼다고 간주하지 않는다.

구형 `scripts/mix-frame-rate-audio.ps1`는20씬/6.5초 예시 전용 구현이므로 slug만 바꿔 범용으로 실행하지 않는다. 현재 실행기/필터/폰트/타이밍을 매니페스트로 확인한다. `scripts/check-video-project.ps1 -Project <slug> -Stage narration|publish`는 해당 단계만 검사하고 통과가 사람 청취나 게시 승인인 것은 아니다.
