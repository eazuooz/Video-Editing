# 내레이션·자막·오디오 제작 기준

이 문서는 이 저장소에서 새 영상을 만들 때 적용하는 기본 오디오 규칙입니다.
프로젝트별 예외가 필요하면 `projects/<slug>/README.md`와 `project.json`에 이유를
기록합니다. 기존 완성작은 보존하고, 새 프로젝트에는 이 기준을 적용합니다.

## 승인 순서

다음 단계를 건너뛰지 않습니다.

1. 장면별 한국어 대본을 검토하고 확정한다.
2. 짧은 TTS 비교 샘플로 목소리·속도·톤을 승인받는다.
3. 전체 TTS, 한국어 SRT와 타이밍 JSON을 생성한다.
4. 전체 음성을 다시 받아써 누락·반복·고유명사 오류를 검토한다.
5. 한국어 타이밍을 유지한 번역 SRT를 생성한다.
6. 사용할 BGM 후보와 라이선스를 먼저 제시하고 명시적으로 선택받는다.
7. 선택 전에는 BGM을 다운로드하거나 최종 영상에 섞지 않는다.
8. 게임 원음과 승인된 BGM을 믹스한 뒤 최종 영상을 렌더한다.
9. 최종 음량, 오디오 스트림, 자막 종료 시간과 영상 길이를 검사한다.

## 기본 TTS 설정

- 모델: `Qwen3-TTS-12Hz-1.7B-Base`
- 언어: 한국어
- 기준 음성: `shared/voice-reference/reference-15-35s.wav`
- 기준 발화문: `shared/voice-reference/reference-15-35s.ko.txt`
- 합성 단위: 문장별이 아닌 **장면별 연속 발화**
- SRT 단위: `narration.ko.json`의 각 `lines` 항목
- 장면 사이 기본 휴지: 0.72초
- 출력 버전: 새 프로젝트는 `qwen3-1.7b-balanced-v1`에서 시작하고, 승인된
  음성을 다시 만들 때는 기존 결과를 덮지 말고 `v2`, `v3`로 올린다.

기준 음성과 발화문은 같은 구간이어야 합니다. 기준 음성은 개인 정보이므로 Git에
올리지 않으며, 렌더된 프로젝트 음성만 필요에 따라 공유합니다.

기준 발화문이 없거나 기준 음성을 바꿨다면 먼저 실행합니다.

```powershell
qwen3-tts/.venv/Scripts/python.exe qwen3-tts/transcribe_reference.py `
  shared/voice-reference/reference-15-35s.wav `
  --output shared/voice-reference/reference-15-35s.ko.txt
```

`ref_text`를 포함한 음성 복제 모드를 사용합니다. 발화문 없이 화자 벡터만 사용하는
모드는 빠른 임시 샘플 외에는 기본 제작 방식으로 사용하지 않습니다.

## TTS 미리듣기와 전체 내레이션 생성

전체 생성 전에 첫 장면 또는 대표 장면으로 미리듣기를 만듭니다.

```powershell
qwen3-tts/.venv/Scripts/python.exe qwen3-tts/generate_sample.py `
  --project <slug> --scene 01
```

기본 출력은 `shared/audio-samples/<slug>-qwen3-1.7b-approval-sample.wav`입니다.
대본과 샘플이 승인된 뒤 저장소 루트에서 전체 패키지를 생성합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File scripts/build-project-narration.ps1 -Project <slug>
```

이 명령은 다음 작업을 순서대로 수행합니다.

1. 장면 단위 TTS와 한국어 SRT·timing JSON 생성
2. 영어 대본이 있으면 같은 타이밍의 영어 SRT 생성
3. Motion Canvas용 장면 타이밍과 `assets/narration.wav` 동기화
4. Whisper 전체 받아쓰기 파일 생성

생성 중 중단돼도 품질 검사를 통과한 장면 WAV는 재사용합니다. 한 장면의 출력이
비정상적으로 길어지는 것을 막기 위해 최대 출력 토큰을 제한합니다.

`chunks/`와 `preview-*` 파일은 다시 만들 수 있는 중간 결과라 Git에 올리지 않습니다.
공유하거나 보관할 결과는 최종 WAV, 한국어·영어 SRT, timing JSON과
`*.asr-review.txt`입니다.

## TTS 품질 기준

- 같은 장면의 문장은 한 번에 읽혀야 한다.
- `~합니다`, `~했습니다`, `~됩니다` 같은 종결 어미가 잘리지 않아야 한다.
- 끝부분 음량과 감쇠 시간을 검사하고 기준 미달 결과는 최대 3번 다시 생성한다.
- 매우 조용하게 닫힌 발음은 끝 단어가 온전히 인식되는지 받아쓰기로 재확인한다.
- 전체 받아쓰기에서 문장 누락, 반복, 숫자와 고유명사 오류를 확인한다.
- SRT 수는 모든 장면의 `lines` 수와 같아야 한다.
- SRT는 겹치거나 역전되지 않아야 하며 마지막 자막은 음성 길이를 넘지 않는다.
- 새 타이밍으로 Motion Canvas를 빌드해 모든 장면이 독립적으로 연결되는지 확인한다.

받아쓰기 결과는 자동 합격 판정이 아니라 검토 자료입니다. 숫자 표기처럼 Whisper가
정규화하는 차이는 허용하지만, 내용이 달라졌다면 해당 장면만 다시 생성합니다.

## 실제 게임 영상과 채널 그래픽

기본 구성은 한 장면 안에서 다음 페어를 사용합니다.

1. 실제 게임·공식 기술 예시 영상 1개: 보통 5~10초
2. 같은 개념을 설명하는 자체 Motion Canvas 또는 Manim 화면 1개

한 화면에는 핵심 개념 하나만 보여 줍니다. 원본 영상의 고유 편집이나 자막 구성을
복제하지 않고, 필요한 동작만 짧게 인용한 뒤 자체 설명 화면으로 전환합니다.

게임 영상은 영상 스트림만 추출하지 않습니다. 유용한 효과음과 환경음은 보존하되,
원본 음악이 권리 문제를 일으킬 수 있으면 효과음 중심 구간을 고르거나 해당 음악만
낮추거나 제거합니다. 원본 링크, 권리자, 사용 구간, 화면과 소리의 사용 근거를
`sources/SOURCES.md`에 기록합니다.

## 음악 선택 승인

내레이션만 있는 자체 그래픽 구간에는 잔잔한 BGM을 사용합니다. 같은 곡을 영상
전체에서 반복해도 되지만 실제 게임 원음과 경쟁하지 않게 조절합니다.

최종 믹스 전에 최소한 다음 정보를 포함한 후보를 제시합니다.

| 항목 | 기록 내용 |
| --- | --- |
| 곡명·아티스트 | 정확한 표기 |
| 미리듣기·원본 링크 | 권리자가 제공한 페이지 우선 |
| 라이선스 | YouTube Audio Library, CC BY 4.0 등 |
| 출처 표기 | 필요 여부와 붙여 넣을 정확한 문구 |
| 사용 범위 | YouTube 전용인지 다른 플랫폼도 가능한지 |
| 영상 적합성 | 톤, 악기, 내레이션 방해 정도 |

YouTube 게시만 고려하면 YouTube Studio 오디오 보관함의 `저작자 표시 필요 없음`
필터를 우선합니다. 외부 라이브러리 곡은 ‘무료’라는 설명만 믿지 말고 원본
라이선스 페이지를 확인합니다. CC BY 곡을 선택하면 설명란에 출처를 반드시 넣습니다.

## 기본 믹스 기준

아래 값은 시작점이며 실제 청취 결과에 따라 조정합니다.

- 내레이션: 중심 트랙, 약 -16 LUFS, true peak -1.5 dBTP 이하
- 게임 원음: 내레이션보다 약 14~18dB 작게
- BGM: 내레이션보다 약 18~24dB 작게
- 음성 중 BGM 덕킹: 추가로 약 4~8dB 감소
- 페이드 인·아웃: 보통 0.3~0.8초
- 게임 원음이 나오는 동안 BGM은 더 낮추거나 잠시 끈다.
- 내레이션, 게임 음악과 BGM 세 요소가 동시에 경쟁하지 않게 한다.

게임 예시 구간에는 작은 원음이 있어야 하고, 게임 영상이 없는 자체 설명 구간에는
승인된 BGM이 있어야 합니다. 단, 침묵이 연출상 필요한 장면은 프로젝트 문서에
의도를 기록합니다.

## 최종 출력과 완료 조건

- 기본 게시본: 1920×1080, 60fps, H.264 + AAC
- 유튜브 본편: 고정 자막 없는 영상과 한국어·영어 SRT를 별도 제공
- 쇼츠나 SNS용으로 필요할 때만 고정 자막 버전을 추가 생성
- `project.json`의 음악 승인 상태와 최종 파일 경로를 갱신
- `scripts/check-video-project.ps1 -Project <slug> -Stage publish` 통과
- 사람이 처음부터 끝까지 듣고 승인한 뒤에만 상태를 `complete`로 변경

## 변경 시 다시 만들어야 하는 것

| 변경한 기준 파일 | 다시 생성할 결과 |
| --- | --- |
| `narration.ko.json` | TTS, 한국어·번역 SRT, timing, Motion Canvas 씬 길이 |
| 기준 음성 또는 발화문 | 모든 TTS 장면과 이후 결과 |
| B-roll 원본·구간 | 정규화 클립, 원음 믹스, 출처표 |
| 선택 음악 | 최종 오디오 믹스, 설명란 출처, 최종 MP4 |
| Motion Canvas·Manim 코드 | 해당 영상 클립과 최종 MP4 |

생성 파일을 직접 고쳐 임시로 맞추지 말고 기준 파일 또는 매니페스트를 수정한 뒤
다시 생성합니다.
