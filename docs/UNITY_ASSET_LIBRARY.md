# 영상 제작용 Unity 에셋 라이브러리

사용 프로젝트는 `unity/VideoEditing`이다. 에셋은 `Assets/ThirdParty/YamyamAssetLibrary` 아래에 제품별 `번호-상품명` 폴더로 배치한다. 번들에서 실제 파일을 확보한83개 제품과 기존 `LittleNightmare` 패키지1개, 총84개가 대상이다. `Godot Project - Grass Wind Shader`와 `Godot Project - Water Shader`는 상품 메타데이터만 있고 실제 에셋 파일이 없어 임포트 대상에 넣지 않았다.

제품 목록·공개 상품 주소·복원 원본·실제 설치 상태는 [에셋 목록](../shared/assets/unity-asset-library.json)에 기록한다. 준비 완료와 실제 Unity 검사 완료를 구분하며, 현재 상태는 목록의 `actualImport`를 확인한다.

## 사용

- Unity의 Project 창에서 해당 제품의 `Prefabs`, 모델, 재질과 애니메이션을 찾는다. 원본 제품 구조와 Unity 참조를 유지한다.
- FBX·텍스처 제공 제품은 제품 폴더의 `Generated` 아래에 생성한 URP 재질·프리팹을 사용한다. 애니메이션 전용 모델은 원본 FBX의 클립을 사용한다.
- 영상별 씬은 기존 `Assets/VideoScenes` 구조에 저장하고 공용 에셋을 참조한다. 라이브러리를 영상마다 복제하지 않는다.
- 제품에 포함된 자동 프로젝트 설정과 일부 선택형 Editor 도구는 기본 실행을 꺼 두었다. 모델·재질·프리팹을 사용하기 위해 이 도구들을 켤 필요는 없다.
- 일부 제품의 오래된 데모 씬과 선택형 효과에는 별도 제약이 있을 수 있다. 제품별 기록과 실제 검사 보고서를 확인한다.

프로젝트는 Unity `6000.6.0f1`, URP `17.6.0`을 기준으로 검사한다. `LittleNightmare`의 런타임 리소스 로더에는 Addressables `2.11.2`가 필요하다. 기존에 잠긴 다른 패키지 버전은 보존한다.

## 원본과 복원

다운로드 원본은 `D:\얌얌코딩 에셋`에 보존한다. 제품 파일·이미지·모델·압축파일은 로컬 전용이며 Git에 올리지 않는다. Git에는 가져오기 도구, 제품 목록, 필요한 패키지 설정과 이 안내만 남긴다.

복원 시 목록의 원본 경로와 로컬 `unity-import-candidates.json`을 사용한다. 준비 도구는 `scripts/import-unity-asset-library.py`, GUID·경로 복구 도구는 `scripts/finalize-unity-asset-library.py`다. 코드 호환성 처리는 [도구 안내](../scripts/unity-asset-library-code/README.md)를 따른다.

실제 Unity 검사와 생성 결과는 `unity/VideoEditing/Library/YamyamAssetLibrary` 아래에 남긴다. `headless-project`는 사용자 편집기와 분리된 숨김 검사 프로젝트다. 정상 종료 후 `record-unity-asset-import.py`로 최종 파일·GUID·생성 결과를 기록하고, `install-unity-asset-library.py`로 검증된 폴더와 대응 `.meta`를 설치한다. 파일 설치기 자체는 기존 씬을 열거나 데스크톱을 조작하지 않는다. 설치 후 정상 Refresh를 위해 기존 Unity 창에 초점을 맞췄다. 후속 Editor의 공급자 씬 로드 기록은 아래 native 이행 범위와 구분한다.

최종 설치 보고서, 검증 보고서와 제품 목록은 기술 검사 범위를 기록한다. 제품별 대표 미리보기는 전체 애니메이션·모든 데모 씬의 시각 검수를 대신하지 않는다. 영상 제작 시 실제 사용 파일과 필요한 출처·크레딧은 해당 영상의 씬 계획에 연결한다.

## 실제 설치 검사

파일 설치 직후에는 주 편집기의 첫 임포트와 최종 확인이 진행 중이었다. 이후 실제 native 확인 결과와 검사 범위는 아래 후속 확인에 별도로 기록한다.

검사 완료본은 `Assets/ThirdParty/YamyamAssetLibrary`에84개 제품, 메타데이터를 포함한129,625개 파일로 설치했다. Unity6000.6.0f1/URP17.6.0 분리 프로젝트의 정상 종료·참조 검사와 전체 파일 SHA/GUID 검증을 통과한 동일 폴더다. 파일 설치기 자체는 기존 씬을 열거나 데스크톱을 조작하지 않았다. 설치 후 정상 Refresh를 유도하기 위해 열려 있던 Unity 창에 초점을 맞췄으며, 작업에서 별도로 씬 열기·전환을 요청하지는 않았다. 다만 후속 Editor 로그에는 공급자 씬의 native 로드·직렬화 이행이 기록됐으며 호출 주체는 확인되지 않았다. 현재 씬 설정은 AiCraftShopSample이다. 실제 검사 시각과 보고서 해시는 제품 목록의 `actualImport`에 남긴다.

- 033의 `Plakat4_terrain`·`New Terrain 6`은 원본에 없는6개 텍스처 GUID를 참조한다. 실제 전체 의존성 검사로 미사용을 확인한 두 TerrainData와 `.meta`4파일을 원본 그대로 보존했다.

## 주 Unity Editor의 후속 확인

실제 AssetDatabase에서 제품84개·폴더를 제외한 에셋62,904개와 새 컴파일 완료를 확인했다. 원래 전체 SHA를 검증해 설치한129,625파일·14,310,047,372바이트와 canonical 목록은 역사적 설치 근거로 보존한다.

후속 native 직렬화에서014의825파일과079의92파일, 합계917파일이 YAML로 바뀌었고079에 LightingSettings 에셋과 메타파일이 생겼다. 현재는129,627파일·14,348,032,508바이트다. 공급자 씬 로드·native 이행 기록은 있지만 이를 시작한 호출 주체는 확인되지 않았다. 모든 외형·GI가 이전과 같다고 주장하지 않는다.

바뀐917파일과 새 LightingSettings1개, 총918개를 별도 native 검사하고 연결된 의존 에셋1,805개를 확인했다. 이 검사에서 누락 스크립트·텍스처·셰이더, 미지원 셰이더, 셰이더 컴파일 오류, 읽기 실패, 외부 에셋 의존은 모두0이었다. 일반 씬 검사는 명시적 스크립트 참조를 확인하며 모든 TerrainData·씬 참조 통과를 뜻하지 않는다. 079의 선택적 원본 씬은 제공 당시부터 TerrainData GUID 72a46daa0efc16a4cbe3333dd097d619를 참조하지만 원본 패키지294개 에셋 항목에는 해당 데이터가 없었다. 이 제한을 별도 기록하며 다른 데이터로 채우지 않았다.
