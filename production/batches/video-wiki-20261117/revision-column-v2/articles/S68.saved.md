## 조건문을 읽는 이해에서 직접 사용하는 이해로 넘어가기

조건문 설명을 읽으면 ‘맞으면 이 코드를 실행한다’는 뜻은 이해할 수 있습니다. 그런데 체력 기능을 직접 만들려고 하면 무엇을 비교하고 어느 순서로 바꿔야 할지 손이 멈춥니다. 설명을 이해하는 것과 새 문제에서 조건을 구성하는 것은 다른 과제이기 때문입니다.

연습은 같은 코드를 여러 번 복사하는 일만이 아닙니다. 결과를 예상하고 실행한 뒤 차이를 설명하며, 도움을 조금씩 줄여 가는 과정입니다. 자체 체력 기능 하나를 예로 문법에서 실제 사용으로 이어지는 연습을 만들어 보겠습니다.

## 먼저 코드 대신 행동의 약속을 쓰기

자체 캐릭터의 최대 체력은 10입니다. 피해를 받으면 체력이 줄고, 체력이 0 이하가 되면 실패 상태가 됩니다. 체력은 화면에 음수로 보이지 않게 0에서 멈추기로 합니다. 이 약속에는 서로 다른 두 가지가 있습니다. 실패 판단과 표시할 체력 범위를 정하는 일입니다.

‘체력이 0이면 실패’라고만 쓰면 -1이 되었을 때 조건을 놓칠 수 있습니다. 피해가 체력보다 클 수 있기 때문입니다. 먼저 체력 1에서 피해 1, 체력 1에서 피해 2, 체력 2에서 피해 1의 결과를 종이에 적습니다. 경계의 양쪽을 보는 연습입니다.

## 값이 어떤 순서로 바뀌는지 추적하기

자체 구현은 피해를 빼고, 체력을 0 이상으로 제한하고, 남은 체력으로 실패를 판단합니다. 여기서 피해는 0 이상이라고 가정합니다. 회복은 나중에 별도 입력으로 추가하겠습니다. 가정을 적어 두면 음수 피해를 넣었을 때 무엇을 해야 하는지도 다음 질문으로 남길 수 있습니다.

```py
def take_damage(hp, damage):
    next_hp = max(0, hp - damage)
    failed = next_hp <= 0
    return next_hp, failed
```

hp는 이전 체력, damage는 이번 피해, next\_hp는 이후 체력입니다. max는 두 값 중 큰 것을 골라 음수가 표시되지 않게 합니다. failed는 실패 여부를 담는 참·거짓 값입니다. 체력 1, 피해 2라면 빼기 결과 -1을 0으로 제한하고 failed는 참이 됩니다.

## 코드를 보기 전에 다음 결과를 예상하기

실행 결과를 먼저 보면 ‘그렇겠네’라고 납득하기 쉽습니다. 그전에 세 입력의 결과를 직접 적어 봅니다. 예상이 틀리면 문법을 몰랐는지, 조건의 의미를 잘못 읽었는지, 계산 순서를 놓쳤는지 구분합니다. 같은 실수라도 다음 연습이 달라질 수 있습니다.

값을 한 번씩만 바꾸어 봅니다. 피해를 0으로 하면 체력과 실패 여부가 유지되는지, 이미 체력 0인 캐릭터에 피해를 주어도 음수가 되지 않는지 확인합니다. ‘아무 입력이나 많이’보다 이번 규칙의 경계가 드러나는 입력을 고르는 연습이 중요합니다.

## 도움을 줄이는 순서를 정하기

처음에는 완성 코드를 읽고 값의 변화를 적습니다. 다음에는 조건식 일부를 빈칸으로 두고 채웁니다. 그다음 행동 설명만 보고 함수를 작성하고, 마지막에는 새 문제에서 어떤 상태와 검사가 필요한지 스스로 정합니다. 모든 단계를 한 번에 건너뛸 필요는 없습니다.

오류가 나면 즉시 완성 답을 복사하기보다 가장 작은 실패 입력을 찾습니다. 그 입력에서 각 줄 뒤의 값을 확인하고 예상과 처음 달라지는 지점을 봅니다. 디버깅도 문법과 별개인 특별 기술이 아니라 상태 변화를 추적하는 연습으로 시작할 수 있습니다.

영상을 다 보았거나 코드를 한 번 실행했다고 끝내기보다, 다른 입력의 결과를 예상하고 왜 그런지 설명할 수 있는지 봅니다. 코드를 가리고 행동 약속에서 다시 구성할 수 있는지도 확인합니다. 반복 횟수 하나가 실력을 보장하지는 않습니다.

작은 기능을 배우고 다른 상황에 옮겨 보고 틀린 이유를 수정하는 고리를 만들면 문법이 실제 도구로 남습니다. 배운 내용이 많아지는 것과 필요할 때 사용할 수 있는 내용이 많아지는 것을 함께 살피는 학습입니다.
