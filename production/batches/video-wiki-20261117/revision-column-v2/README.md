# 개발 방법론 칼럼으로 다시 쓰기

2026-11-17 사용자 검수: 기존 113장에 설명과 이미지가 부족하고 요약처럼 느껴진다. 영상과 같은 순서일 필요가 없으며, 각 개발 방법론을 독립적인 칼럼으로 쉽게·상세히 설명한다. 필요한 외부 그림도 조사해서 사용할 수 있다.

## 실제 변경 범위

기존 113개의 학습 페이지 주소·부모·영상 연결·유용한 그림을 보존하며 다시 쓴다. 일상·패러디 15편은 보관 목록으로 유지한다. 영상 자체를 재제작하거나 플랫폼 설정을 바꾸지 않는다.

## 이번 검수에서 달라져야 하는 것

- 제목과 용어만 소개하지 않는다. 한 가지 상황을 설정하고 입력/현재 상태 → 내부 처리/판단 → 다음 상태/보이는 결과를 단계별로 연결한다.
- 처음 보는 용어는 정의와 작은 사례를 붙여 설명한다. 수식은 구할 대상과 기호를 먼저 밝히고, 코드와 자료구조는 왜 필요한지까지 설명한다.
- 기술 칼럼은 자료 표현·알고리즘/처리 순서·의사코드/작은 구현·실패 사례·적용 조건을 다룬다. 디자인 칼럼은 의사결정·비교할 대안·플레이어의 실제 행동·프로토타입과 검증 방법을 다룬다.
- 기존 영상의 사례는 출발점으로만 활용한다. 게임 내부를 확인한 사실, 외부 개발자/공식 자료, 우리가 만든 설명용 모형을 구별한다. 확인하지 않은 게임 구현을 사실로 단정하지 않는다.
- 이미지는 본문의 특정 질문에 답해야 한다. 전후 상태·좌표·흐름·구성 요소를 실제로 보여 주고, 바로 앞뒤 문단에서 읽는 법을 설명한다. 장식용 카드·같은 화면 반복·글의 요약 문장을 그림 안에 옮기는 방식은 피한다.
- 실제 영상 프레임은 유지하되 충분하지 않으면 직접 만든 과정 도식과 출처·사용 조건이 확인된 외부 그림을 보충한다. 외부 그림에는 저자·원문·라이선스·변경 여부를 남긴다.
- 문서 길이·이미지 개수·링크 저장 성공만으로 완료 처리하지 않는다. 독자가 단계마다 무엇이 달라졌는지 말할 수 있는지, 예제를 스스로 재현하고 틀린 경우를 진단할 수 있는지 검수한다.

## 기록

`progress.json`은 글별 실제 작성/그림/출처/Notion 반영/검수 상태를 분리한다. 이전 배치의 저장 완료 이력은 이번 칼럼 품질 완료를 뜻하지 않는다. `articles/`에 새 원고, `sources.json`에 검증 자료, 상위 `evidence/column-v2/`에 그림과 저장 결과를 둔다.
