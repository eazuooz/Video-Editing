# 제작 계획 — v5 전체 음성 검토본

2026-09-07: 승인된 v4에서 테트리스·밈·흰색 발표형·예시 길이 확장 요청을 반영. v5 수정 대사는 재검토 대상입니다. 12개 독립 씬과 **예시 영상 19.5초 → 자체 설명** 페어를 구현했습니다.

## 현재 결과

- 2026-09-11 전체 TTS 연결: 15분6.733초. 이전14분11초 임시값 대신 실제 발화를 기준으로 씬·한영 SRT·믹스·편집 큐를 함께 갱신.
- [실제 컷 대응표](../sources/FOOTAGE.md): 12개의 예시 페어. 일반 스톡 6개를 서로 다른 게임개발 영상으로 교체. 편집기·코딩·프로토타입·최적화·완성·플레이 테스트 화면 사용.
- 각 컷 1920×1080, 60fps, 1170프레임. 원음 스트림과 믹스 구간 검사.
- 전체 12쌍의 대표 화면을 로컬 브라우저에서 렌더하고 코드 오류·잘림을 검토.
- 사용자 요청에 따라 기존 균형형 화자로 전체12챕터 합성. 말끝 검사·받아쓰기 대조 완료, 주관적 전체 청취 승인은 별도.
- BGM은 Blue Dream — Cheel로 선택 확정. 보관함 파일·라이선스 확인 대기. 현재 편집기 오디오는 원음12개와 전체 v5 TTS를 포함.

## 씬별 자체 시각화

1. 오늘 체크리스트 / 과장된 AI 헤드라인
2. 가상 사장·임원·팀장 / 기대와 검증 구분
3. range(4) → range(5), 출력과 횟수
4. 요청 대기열 / 이름으로 데이터 조회
5. 과도한 구조 → 요구사항에 맞게 단순화
6. 중복 이름 제거: 입력 → 원하는 출력 → seen/result
7. 실제 테트리스 플레이 → 10×20 배열·충돌·고정·4줄 삭제
8. 벽 옆 회전·블록 충돌·동시 줄 삭제·종료 뒤 입력
9. 기본 API 단가 / 사용량·재시도·캐시 / 월 구독료 구분
10. 합의된 완료 기준 / 실패 처리 / 구체적인 진행 보고
11. 미리 준비된 Python 환경에서 로컬 메모 파일 만들기
12. 작은 시작 → 검증·완료 → 내 말로 설명

## 공통 디자인·편집 기본값

[흰색 발표형 기준](../../../docs/VIDEO_VISUAL_STYLE.md)과 `project.json.editing` 적용.
각 씬 설명 시작 2초간 자체 밈을 겹칩니다. 추가 시간 없이 설명 구간 안에서 재생합니다.
실제 예시는19.5초이며 현재 전체906.733초 중234초, 약25.8%를 차지합니다. 초기851.03초 초안의 비율은27.5%였습니다. 이전 컷은 캐시 archive-v1 및 archive-v2에 보존했습니다.

## 남은 단계

1. 전체 음성본 청취 승인, 선택된 Blue Dream 보관함 파일·라이선스 확보.
2. 전체 장면 단위 TTS / 영어 번역 / 한영 SRT / ASR 자동 검수는 완료. 사람의 최종 청취에서 수정이 필요하면 해당 장면만 다시 생성.
3. 설명 도식은 실제 장면 길이에 연결되어 있으며 추가 강조 시점은 청취 검토 후 조정.
4. 승인된 음악을 처음부터 끝까지 연속 재생, 원음과 동시 믹스.
5. 최종 MP4와 같은 오디오를 Motion Canvas에 연결.
6. 출처·요금·최종 화면·자막 싱크 전수 검수.

현재 전체 내레이션·원음은 연결되어 있지만 음악과 청취 승인이 남아 있어 게시용 최종 렌더로 표시하지 않습니다. 초기 후보 목록은 조사 이력이고 실제 선정은 `sources/selected-footage.json` 한 곳을 기준으로 합니다.
