# 17. 대학교 1, 2학년이라면 백지에서 시작해보세요

그리고 이건 제가 컴퓨터공학과 1, 2학년 학생들에게 특히 강조하고 싶은 이야기입니다.

**대학교 1, 2학년 때는 AI를 끄고, 가능하면 정답 코드도 보지 않은 상태에서 백지부터 직접 프로그램을 만들어보세요.**

여기서 제가 말하는 '직접 만든다'는 것의 의미가 중요합니다.

AI가 만들어준 코드를 보고 따라 작성하는 것만 이야기하는 게 아닙니다.

인터넷에서 다른 사람의 코드를 찾아서 따라 만드는 것,

유튜브 강의를 보면서 강사가 작성하는 코드를 그대로 따라 치는 것,

책에 있는 완성된 예제 코드를 옆에 펼쳐놓고 그대로 작성하는 것.

이것들도 제가 지금 이야기하는 **백지에서 프로그램을 만드는 훈련과는 다릅니다.**

물론 이런 공부 방법 자체가 나쁘다는 이야기는 아닙니다.

처음 개념을 배울 때는 책의 예제도 봐야 하고,

강의도 봐야 하고,

다른 개발자의 좋은 코드도 많이 읽어봐야 합니다.

**하지만 코드를 읽어서 이해하는 훈련과, 아무것도 없는 상태에서 코드를 만들어내는 훈련은 구분할 필요가 있습니다.**

# 18. 공부한 다음에는 정답을 닫으세요

예를 들어 Linked List를 공부한다고 해보겠습니다.

처음에는 책을 봅니다.

Node가 무엇인지 배우고,

Pointer가 어떻게 다음 Node를 가리키는지 배우고,

삽입과 삭제가 어떤 원리로 이루어지는지 공부합니다.

여기까지는 당연히 자료를 봐야 합니다.

그런데 공부가 끝났다면 책을 닫아보세요.

인터넷도 끄고,

AI도 끄고,

예제 코드도 닫습니다.

그리고 빈 프로젝트를 하나 만듭니다.

화면에는 이것만 있는 겁니다.
```csharp
int main()
{

}
```

그리고 시작해보세요.

**Linked List를 직접 만들어보는 겁니다.**

처음에는

“Node를 어떻게 만들었더라?”

부터 막힐 수도 있습니다.

괜찮습니다.

그 막히는 순간이 바로 여러분이 아직 자기 것으로 만들지 못한 부분입니다.

# 19. 테트리스도 똑같습니다

테트리스 만드는 유튜브 강의를 처음부터 끝까지 따라 했다고 해보겠습니다.

영상에서는 강사가

Board를 만들고,

Block을 만들고,

Collision을 만들고,

Rotation을 만들고,

Line Clear를 구현합니다.

학생도 똑같이 따라 합니다.

마지막에는 테트리스가 실행됩니다.

그런데 여기서 한 번 더 해봐야 합니다.

프로젝트를 닫으세요.

강의도 끄세요.

소스코드도 보지 마세요.

그리고 새로운 빈 프로젝트를 만드세요.

그 상태에서 다시 테트리스를 만들어보는 겁니다.

그러면 갑자기 완전히 다른 문제가 됩니다.

“뭐부터 만들지?”

“블록 데이터는 어디에 저장하지?”

“보드는 2차원 배열로 해야 하나?”

“충돌 검사는 언제 하지?”

“블록을 어떻게 회전시키지?”

“게임 루프는 어떤 순서로 돌지?”

이 질문에 **강사가 아니라 내가 답해야 합니다.**

제가 말하는 코딩 훈련은 바로 이 과정입니다.

# 20. 코드를 읽는 것과 코드를 생성하는 것은 다릅니다

이 차이를 굉장히 중요하게 생각합니다.

AI가 만들어준 코드를 읽고

“아, 이렇게 하면 되는구나.”

라고 이해하는 것.

책의 예제를 읽고

“아, Linked List는 이렇게 구현하는구나.”

라고 이해하는 것.

다른 사람의 GitHub 코드를 보고

“이 사람은 이런 구조를 사용했구나.”

라고 이해하는 것.

이런 공부도 필요합니다.

하지만 그것만 반복하면 **Recognition, 즉 보고 알아보는 능력**을 주로 훈련하게 됩니다.

반면 백지에서 프로그램을 만드는 것은 다릅니다.

정답이 눈앞에 없습니다.

내가 기억해야 하고,

내가 문제를 나눠야 하고,

내가 자료구조를 결정해야 하고,

내가 함수와 클래스를 만들어야 하고,

내가 구현 순서를 정해야 합니다.

그리고 틀리면 내가 원인을 찾아야 합니다.

이건 **Recall과 Problem Solving을 함께 사용하는 훈련**에 더 가깝습니다.

# 21. 영어 회화로 다시 생각해보면 쉽습니다

영어 문장 1,000개를 읽었다고 해보겠습니다.

문장을 보면 전부 해석할 수 있습니다.

그런데 책을 덮고 외국인이 앞에 앉습니다.

갑자기 아무 말도 나오지 않을 수 있습니다.

왜냐하면

**영어를 보고 이해하는 것과 내 생각을 영어 문장으로 만들어내는 것은 다른 훈련이기 때문입니다.**

프로그래밍도 비슷합니다.

Linked List 코드를 10번 읽는 것과

Linked List를 백지에서 10번 만드는 것은 같은 훈련이 아닙니다.

테트리스 코드를 이해하는 것과

빈 프로젝트에서 테트리스 구조를 스스로 만들어내는 것도 같은 훈련이 아닙니다.

그래서 제가 학생들에게 권하고 싶은 공부 방법은 단순합니다.

**배울 때는 보세요.**

책도 보고,

강의도 보고,

AI에게 설명도 들어보세요.

하지만 어느 정도 이해했다면,

**전부 닫으세요.**

그리고 백지에서 다시 만들어보세요.

# 22. 막히는 것이 공부입니다

여기서 중요한 게 하나 있습니다.

백지에서 시작하면 당연히 막힙니다.

그게 정상입니다.

Node 선언부터 기억이 안 날 수도 있습니다.

Pointer가 헷갈릴 수도 있습니다.

충돌 검사를 어떻게 해야 할지 한참 고민할 수도 있습니다.

버그 하나를 두 시간 동안 못 찾을 수도 있습니다.

그런데 저는 그 시간이 굉장히 중요하다고 생각합니다.

정답 코드를 옆에 놓으면 10초 만에 해결할 문제를

30분 동안 생각하고,

코드를 바꿔보고,

Breakpoint를 걸고,

변수를 확인하고,

실패하고,

다시 만들어보는 겁니다.

**그 과정에서 문제를 코드로 바꾸는 능력이 훈련됩니다.**

목표가 과제를 빨리 끝내는 것이라면 AI를 사용하는 것이 훨씬 효율적입니다.

하지만 목표가 프로그래밍을 배우는 것이라면,

항상 가장 빠른 길이 가장 좋은 학습 방법은 아닐 수 있습니다.

# 23. 그래서 저는 1, 2학년과 3, 4학년의 AI 사용을 다르게 봅니다

대학교 1, 2학년이라면 저는 의도적으로 이런 시간을 많이 가져보는 것을 권하고 싶습니다.

자료구조를 공부했다면 정답을 닫고 직접 구현해보세요.

알고리즘을 공부했다면 해설을 닫고 다시 풀어보세요.

게임 프로그래밍을 공부했다면 강의를 다 본 다음 빈 프로젝트에서 다시 만들어보세요.

그리고 가능하면 AI에게 정답 코드를 바로 요청하지 마세요.

**백지에서 생각하고 코드를 만들어내는 시간을 충분히 가져보세요.**

반대로 기본적인 프로그래밍 숙련도가 만들어진 이후에는 AI를 적극적으로 사용해도 좋다고 생각합니다.

3, 4학년이 되면서 프로젝트 규모가 커진다면 AI를 이용해서 생산성을 높여보세요.

반복 코드를 생성하고,

라이브러리를 조사하고,

테스트 코드를 만들고,

리팩터링 아이디어를 얻고,

모르는 기술을 빠르게 공부하는 데 활용하세요.

그리고 실무에 들어가면 AI를 강력한 생산성 도구로 사용할 수 있습니다.

제가 말하고 싶은 건

**“AI를 사용하지 마세요.”**

가 아닙니다.

**“프로그래밍을 배우는 시기에 생각하는 과정까지 외주 주지 마세요.”**

라는 겁니다.

# 24. 결과적으로 목표는 이것입니다

AI 없이 개발하는 사람이 되는 게 목표가 아닙니다.

책을 안 보는 개발자가 되는 것도 아닙니다.

검색하지 않는 개발자가 되는 것도 아닙니다.

실무에서는 당연히 문서를 찾아보고,

기존 코드를 읽고,

Stack Overflow도 보고,

AI도 사용하고,

동료에게도 물어봅니다.

하지만 그런 도구들을 사용할 때

**내 머릿속에도 문제를 프로그램으로 바꾸는 능력이 존재해야 합니다.**

그래서 저는 컴퓨터공학과 학생이라면 적어도 1, 2학년 동안은

**백지에서 프로그램을 만들어보는 경험을 정말 많이 해봤으면 좋겠습니다.**

배운 다음에는 책을 닫으세요.

강의를 끄세요.

AI도 끄세요.

그리고 빈 프로젝트를 여세요.

**아무것도 없는 곳에서 직접 시작해보세요.**

처음에는 정말 못합니다.

그런데 그것을 반복하다 보면 어느 순간 문제를 보는 순간 코드의 구조가 머릿속에 그려지기 시작합니다.

그때 AI를 다시 사용해보세요.

그때부터 AI는 여러분 대신 생각하는 도구가 아니라,

**여러분이 생각한 것을 훨씬 빠르게 구현해주는 도구가 됩니다.**
