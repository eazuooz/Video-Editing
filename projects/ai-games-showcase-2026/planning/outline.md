## 사이에 들어갈 AI 소개 영상

소개는 해당 게임의 구체적인 작업을 이어받는다. 공식 기능 화면 또는 출처가 확인된 시연을 바탕으로 요청 → 작업 → 결과를 짧게 보여 준 뒤 게임으로 돌아온다. 설명용 흐름도는 그 사실을 표시하며 제작자의 실제 작업 화면으로 꾸미지 않는다. 모든 삽입 화면은 아래 문단 번호에 연결되어 있고 정확한 시간은 TTS 실측 뒤 확정한다.

## 전체 대본

고유명사는 화면 표기로 적었다. 음성 생성용 한글 발음과 화면·자막의 정식 표기는 별도로 관리한다.

### 01. 게임부터 보자

안녕하세요, 얌얌코딩입니다. 물고기를 낚고, 미래의 트랙을 달리고, 신들의 다음 공격을 예측하는 게임. 이 작품들의 제작 과정에는 어디까지 AI가 들어갔을까요?

오늘은 여섯 게임의 실제 모습을 보면서, 제작자가 밝힌 개발 기간과 실행 환경, 사용한 엔진을 살펴보겠습니다. 중간중간 등장하는 AI도 어떤 일을 맡았는지 짧게 알아볼게요. 빠르게 만든 초기 버전과 여러 주 동안 다듬는 게임은 구분해서 보겠습니다.

먼저, 바닷속까지 들여다보이는 이 작은 섬으로 가보죠.

화면 구성: 섬의 낚시 → 미래 레이싱 → 전술 선택을 한 화면씩 짧게 보여 준다. 소개의 섬 장면을 02 첫 화면으로 이어받는다.

다음 연결: 개요의 섬을 다음 낚시 장면이 그대로 이어받는다.

### 02. I Just Wanted to Fish

I Just Wanted to Fish는 섬을 돌아다니며 낚시하는 게임입니다. 모래사장에 선 캐릭터가 낚싯대를 드리우고, 얕은 물 아래에는 물고기와 산호가 보이죠. 해변에는 작은 게도 돌아다닙니다.

Steam에 출시를 준비 중인 PC 게임이고, 게임 엔진은 Unity 6입니다. 게임 엔진은 캐릭터 조작과 충돌, 화면 표시 같은 기능을 묶어 게임이 돌아가게 하는 기반이에요. 이 작품은 Unity의 고품질 화면 처리 방식인 HDRP를 사용했습니다.

제작자가 공개한 작업 기간은 거의 삼 주입니다. 개발 중인 버전을 소개한 시점의 기간이고, 출시까지 끝났다는 뜻은 아닙니다.

> **삽입 영상 — Claude Opus 5.5 · Claude Code**
>
> 공식 제품명·기능 화면을 보여 준 뒤, 요청 → 코드 작업 → 확인 흐름을 순서대로 연결한다. 모델과 작업 도구 라벨을 나란히 구분한다.

여기서 사용한 AI부터 잠깐 볼게요. Claude Opus 5.5는 Anthropic의 AI 모델입니다. 요청과 코드를 읽고, 필요한 코드를 만들거나 수정하는 데 쓰입니다. 이 게임에서는 제작자가 원하는 물체와 움직임을 구현하는 작업에도 활용했어요.

함께 등장하는 Claude Code는 모델의 이름이 아니라 개발 작업을 수행하는 도구입니다. 프로젝트 파일을 읽고 고치고, 명령을 실행하며 작업을 이어 갑니다. 오퍼스가 요청을 해석하고 코드를 만드는 모델이라면, Claude Code는 그 모델을 실제 작업 환경에서 쓰게 해 주는 도구인 셈이죠.

> **삽입 영상 — MCP · Blender · Unity 연결**
>
> Blender → 모델·애니메이션 → Unity 흐름을 그리며 MCP 연결 지점을 표시한다. 설명용 구성임을 표시한다.

여기에 제작 프로그램을 연결하는 규격이 MCP입니다. 이 규격을 이용한 Blender MCP와 Unity MCP로 AI의 작업을 각 프로그램에 연결했습니다. Blender는 입체 모델과 애니메이션을 만드는 프로그램이고, Unity는 그것들을 움직이는 게임으로 연결합니다.

다시 해변을 보면, 캐릭터와 게의 모양을 만드는 일, 움직임을 붙이는 일, 물과 지형 속에 배치하는 일이 한 장면 안에 모여 있죠. 제작자는 배치를 직접 정하고 참고 그림을 주면서, 나온 결과를 여러 번 수정했습니다.

그리고 이 게임의 Steam 안내에는 플레이 중에는 AI를 사용하지 않는다고 적혀 있습니다. 제작할 때 AI의 도움을 받았다는 것과, 게임을 하는 동안 AI가 매번 답을 만들어 낸다는 것은 구분해야겠죠.

이 작품이 Unity로 만든 PC 게임이라면, 다음 작품은 브라우저에서 바로 들어갈 수 있는 작은 세계입니다.

화면 구성: 낚시·게의 실제 영상 → Steam 출시 상태와 Unity6/HDRP 표시 → Claude·MCP 소개 → 같은 해변 결과. Steam의 플레이 중 AI 미사용 문구는 해당 문장에만 연결한다.

다음 연결: Unity 기반 PC 게임에서 웹페이지로 들어가는 다음 게임으로 실행 환경을 연결한다.

### 03. Emberfall — Luminati

Emberfall — Luminati입니다. 캐릭터는 도트 그림처럼 보이지만, 집과 길이 놓인 공간은 카메라를 돌려서 다른 각도로 볼 수 있습니다. 그림을 올려놓은 작은 모형 마을 같은 느낌이죠.

게임 플레이 페이지와 레벨 에디터가 따로 공개되어 있습니다. 플레이 페이지는 별도 설치 없이 브라우저에서 실행하고, 캐릭터 이동과 카메라 회전을 직접 확인할 수 있었어요. 레벨 에디터에서는 지형 높이와 물건, 조명을 다룰 수 있습니다. 두 주소는 설명란에 구분해서 넣어 둘게요.

편집기는 Luminati라는 이름과 Three.js 기반이라는 표시를 사용합니다. Three.js는 브라우저에 입체 장면을 그리는 기능을 모아 둔 그래픽 라이브러리예요. 이 위에 게임 규칙과 편집 기능을 더해, 지금 보이는 마을을 만들고 움직이게 한 겁니다.

다만 정확한 AI 모델 버전과 전체 개발 기간은 제작자의 일차 자료에서 확인하지 못했습니다. 현재 화면으로 확인되는 제작 기반과, 아직 확인되지 않은 제작 이력은 나누어 볼게요.

여기까지는 작은 세계의 모양과 공간을 봤습니다. 다음 낚시 게임에서는 그 공간에 이야기와 여러 시스템을 계속 쌓아 가는 과정을 볼 수 있어요.

화면 구성: 본게임 /game의 타이틀·마을·카메라 화면 → 레벨 에디터 /editor의 지형·물건·조명 도구. 플레이 페이지와 편집기를 각각 표시하고, 설명란에도 링크를 분리한다. 기존 FHD 게임 캡처를 재사용하며 정지 캡처를 연속 플레이로 꾸미지 않는다.

다음 연결: 작은 세계의 공간 구성에서 그 안에 이야기·시스템을 채우는 Nightshoal로 넘어간다.

### 04. Nightshoal

Nightshoal도 낚시와 탐험을 다루지만, 분위기는 다릅니다. 절벽과 숲 사이로 물길이 이어지고, 배가 그 안을 지나갑니다. 제작자는 여기에 퀘스트와 이야기, 낚시와 인벤토리 시스템을 계속 더하고 있습니다.

이 작품은 Windows PC용으로 내려받아 실행하는 개발 중인 게임입니다. 아직 정식 데모 이전 단계의 공개 빌드이고, 엔진은 Godot입니다. 입체 공간과 게임의 동작을 Godot 프로젝트 안에서 함께 구성한 거예요.

공개된 개발 기록은 십일 주 차입니다. 최근 작업에는 Claude Opus 5.5를 사용했고, 이전에는 Codex Astra도 함께 썼다고 밝혔습니다.

> **삽입 영상 — Codex · Astra의 역할**
>
> 공식 Codex 기능 화면과 파일 수정 → 확인 흐름. Codex=에이전트, Astra=제작자 표기 모델로 구분하고 미공개 API 버전은 적지 않는다.

Codex는 OpenAI의 코딩 에이전트입니다. 에이전트란 요청을 받은 뒤 파일을 고치고 결과를 확인하는 것처럼, 여러 작업을 이어 수행하는 도구를 말해요. 제작 기록의 Codex는 작업 도구, Astra는 사용한 AI 모델의 이름으로 구분하면 됩니다.

> **삽입 영상 — Tripo AI — 입체 모델**
>
> 공식 시연에서 입력 이미지/설명과 회전하는 모델 결과를 보여 준다. 실제 게임 모델로 확인되지 않은 샘플은 도구 기능 예시라고 표시한다.

코드를 다루는 AI만으로 이 풍경을 전부 채운 것은 아닙니다. 복잡한 입체 모델에는 Tripo AI를 사용했다고 해요. 트리포는 문장이나 이미지를 입력받아 입체 모델을 만드는 도구입니다. 다만 생성된 모델을 게임에 배치하고, 크기와 동작을 맞추는 작업은 이어서 필요하죠.

> **삽입 영상 — OpenAI 이미지 생성 API**
>
> 이미지 생성·수정 공식 화면의 입력과 결과를 짝지어 보여 주고, 프로그램 → 이미지 요청 화살표를 추가한다. 제작자의 정확한 모델 버전은 미공개로 표시한다.

그림 작업에는 OpenAI의 이미지 생성 API도 사용했습니다. API는 프로그램에서 생성 기능을 요청할 수 있는 연결 창구예요. 문장이나 참고 그림으로 이미지를 만들거나 수정하는 기능이고, 이 작품에서 쓴 정확한 이미지 모델 버전은 공개되지 않았습니다.

> **삽입 영상 — ElevenLabs 효과음 · Stable Audio 음악**
>
> 효과음 생성과 음악 생성의 공식 기능 화면을 차례로 보여 준다. 동작 한 번의 짧은 소리와 장면 전체의 음악 구간을 길이 도식으로 구분한다.

풍경에 소리가 더해지는 과정도 볼까요. ElevenLabs의 효과음 생성은 원하는 소리를 글로 설명해 만드는 기능입니다. 반면 이 제작자가 음악에 사용한 Stable Audio는 분위기와 스타일을 설명해 음악을 만드는 데 활용했습니다. 한 번의 동작에 붙는 효과음과 장면을 이어 주는 음악을 나누어 준비한 거예요.

이렇게 만든 모델과 이미지, 소리가 같은 게임 안에서 어울려야 합니다. 단순한 모델에는 Blender MCP도 사용했고, 제작자는 지도와 기능을 계속 다듬었다고 설명합니다. 무엇을 만들지 정하고, 결과를 확인하고, 서로 맞지 않는 부분을 고치는 일이 남아 있는 거죠.

여기서는 여러 도구가 세계를 채웠습니다. 다음 게임에서는 그 세계를 빠르게 움직일 때, 조작과 화면이 어떻게 따라오는지 보겠습니다.

화면 구성: 숲·절벽·물길 환경 영상 → Windows 공개 빌드·Godot 표시 → 코딩·3D·이미지·소리 AI 소개를 작업별로 연결 → 같은 게임으로 모이는 흐름. 퀘스트·인벤토리는 제작 기록에 근거하며 항공 영상으로 증명했다고 하지 않는다.

다음 연결: 세계 채우기에서 빠르게 움직일 때 필요한 조작·화면 반응으로 초점을 옮긴다.

### 05. VECTOR: Anti-Gravity Racing

VECTOR: Anti-Gravity Racing입니다. 바퀴 대신 공중에 뜬 기체로 트랙을 달립니다. 코너를 통과하고, 가속 구간을 밟고, 다른 기체와 순위를 겨루죠.

이 게임도 웹페이지에서 실행하는 브라우저 게임입니다. 기반은 앞서 본 Three.js예요. 작은 모형 마을과 빠른 레이싱이 같은 그래픽 라이브러리 위에서 만들어진 셈이죠.

화면을 그릴 때는 브라우저가 그래픽 처리 장치를 사용하게 해 주는 WebGPU를 활용합니다. 제작자는 이를 지원하지 않는 환경을 위해 WebGL 2 방식도 마련했다고 설명해요. 둘 다 화면을 그리는 데 쓰는 그래픽 인터페이스이고, AI 모델이나 게임 엔진 이름은 아닙니다.

제작자는 코딩을 AI와의 대화로 진행했고, 모델 제작에는 Blender를 사용하도록 AI에 요청했다고 밝혔습니다. 다만 정확한 개발 기간과 AI 모델 버전은 확인되지 않아, 특정 모델 하나의 성과로 단정할 수는 없습니다.

빠른 화면만큼 흥미로운 것은 정반대로, 시간을 멈추고 한 수씩 생각하게 만드는 게임입니다.

화면 구성: 코너·가속 실제 영상 → 브라우저/Three.js 표시 → WebGPU·WebGL2 경로를 짧게 설명 → 계속되는 주행. 실제 기체/가속 지점만 표시하고 가짜 성능 수치를 만들지 않는다.

다음 연결: 빠른 레이싱 입력과 시간을 멈추는 전술 선택을 대비한다.

### 06. AUGURY: Duel of the Gods

AUGURY는 신들이 싸우는 게임인데, 버튼을 빠르게 누르는 방식과는 다릅니다. 행동을 고르는 동안 시간이 멈추고, 이동을 선택하면 초록색 모습으로 예상 위치를 보여 줍니다. 선택을 확정한 뒤에 결과가 진행돼요. 상대가 무엇을 할지 예상하는 판단이 중심입니다.

itch.io의 웹페이지에서 바로 실행하는 브라우저 게임이고, 제작 기반은 Phaser와 TypeScript입니다. Phaser는 화면 표시와 입력 같은 기능을 갖춘 이차원 게임 프레임워크예요. TypeScript는 게임 규칙을 코드로 작성하는 언어입니다.

> **삽입 영상 — DreamLayer · ImageGen 표기**
>
> DreamLayer의 참조 이미지→다른 모습 생성 기능을 공식 화면으로 소개한다. AUGURY 개발 기록의 ImageGen 표기는 확대하되 정확한 모델명 아님을 짧게 표시한다.

캐릭터와 소품을 준비하는 과정에는 DreamLayer가 등장합니다. DreamLayer는 원하는 이미지를 설명하면 이미지 모델을 선택해 작업을 진행하는 창작용 AI 에이전트예요. 참고 캐릭터를 주고 다른 모습의 이미지를 이어 만드는 용도로도 쓸 수 있습니다.

제작 보고서에는 ImageGen이라는 이미지 생성 도구 표기도 나옵니다. 생성과 이미지 수정에 썼다는 기록은 있지만, 이것만으로 정확히 어떤 모델을 사용했는지는 알 수 없습니다. DreamLayer와 이미지 생성 도구를 게임 엔진과 구분해서 봐야 하는 이유죠.

다시 캐릭터의 움직임을 보면, 한 장의 그림을 얻는 것과 게임에서 움직이게 하는 것은 별개의 작업입니다. 제작자는 배경을 지우고, 크기와 색을 정리하고, 몸과 소품의 겹치는 순서와 움직임을 맞췄습니다. Python으로 만든 보조 도구와 자체 편집 도구도 사용했어요.

이 작품의 전체 개발 기간은 공개 자료로 확정할 수 없었습니다. 다만 생성된 이미지를 선택과 전투가 읽히는 게임 화면으로 바꾸는 과정은 제작 기록에서 확인할 수 있죠.

이런 손질이 필요하다는 점은, 다음의 짧은 제작 기간을 볼 때도 함께 기억할 만합니다.

화면 구성: 이동 전 → 초록 예상 위치 → 확정 후 실제 위치 캡처 → Phaser/TypeScript 역할 → DreamLayer 소개 → 같은 캐릭터와 제작 보고서의 손질 과정.

다음 연결: 이미지 후처리의 실제 작업을 이어받아 다음 게임의 초기 3일이라는 기간을 해석한다.

### 07. Rally Road Rash

Rally Road Rash는 흙길에서 차량이 부딪치고, 점프대를 넘고, 로켓까지 사용하는 레이싱 게임입니다. 제작자는 약 사흘 만에 초기 버전을 만들었다고 밝혔습니다.

> **삽입 영상 — Sandscape — 브라우저 게임 제작 플랫폼**
>
> 공식 제작 화면의 요청·시각 편집·공유 기능을 순서대로 강조한다. 실행 환경=브라우저, 내부 엔진=미확인으로 구분한다.

이 작품은 Sandscape에서 공개된 브라우저 게임입니다. Sandscape는 글로 게임을 요청하고, 편집 화면이나 코드로 다듬어 공유하는 제작 플랫폼이에요. 다만 이 게임의 내부 엔진까지 공개 자료에서 확인되지는 않았습니다.

> **삽입 영상 — GPT-6 Astra · Opus 작업 분담**
>
> GPT-6 Astra 공식 모델명과 코드 작업 역할을 짧게 소개한다. 제작자 기록의 Opus5.5→물리, Astra6→화면 화살표를 실제 차량 장면에 붙인다.

차량과 물리 코드는 앞서 소개한 Opus 5.5, 화면을 다듬는 작업에는 제작자가 Astra 6라고 부른 모델을 사용했습니다. GPT-6 Astra는 OpenAI의 AI 모델로, 코드 작성과 복잡한 문제 해결에 쓰입니다. 여기서는 두 모델이 맡은 작업이 달랐다는 점이 흥미롭죠.

> **삽입 영상 — Meshy — 차량·소품 모델**
>
> 공식 이미지/문장→3D 모델 시연을 사용하고 모델을 회전해 입체 형태를 보여 준다. 이 시연 결과가 Rally의 실제 차량이라는 오해를 피한다.

차량의 모양에는 또 다른 도구가 들어갑니다. Meshy는 문장이나 이미지를 입체 모델로 바꾸는 생성형 AI 도구예요. 제작자는 주요 차량과 소품에 Meshy를 사용하고, 단순한 배경 물체는 코드로 만든 도형을 함께 썼다고 설명합니다.

모델이 준비된 뒤에는 충돌과 움직임을 맞춰야 합니다. 화면에서 차가 점프하고 땅에 닿는 결과는, 차체 모양과 게임의 물리 동작이 함께 만들어 내는 거죠. 입체 모델을 생성했다고 주행감까지 자동으로 완성되는 것은 아닙니다.

> **삽입 영상 — ElevenLabs — 음악 생성**
>
> 음악 생성 기능 화면에서 분위기·장르 입력과 음악 결과 구간을 연결한다. 사용 모델 세부 버전은 미공개, 효과음 기능과 별도로 표시한다.

음악에는 ElevenLabs를 사용했다고도 밝혔습니다. 앞서 나온 효과음 생성과 별도로, 이 회사에는 분위기나 장르를 설명해 음악을 만드는 기능이 있어요. 다만 이 작품에서 사용한 음악 모델의 세부 버전은 공개되지 않았습니다.

제작자는 레벨을 직접 편집했고, 이십오 년의 경험이 있다고 밝혔습니다. 오토바이의 물리 동작도 아직 다듬는 중이라고 했어요. 사흘이라는 숫자는 이런 초기 버전의 기록입니다. 누구나 같은 시간 안에 같은 결과를 낸다는 보장은 아니죠.

그래서 여섯 게임을 나란히 놓으면, 개발 기간의 숫자보다 더 분명하게 보이는 변화가 있습니다.

화면 구성: 흙길·점프·충돌 실제 영상 → Sandscape 소개 → 두 모델의 작업 분담 → Meshy 소개 → 실제 착지 → 음악 기능 소개 → 제작자 작업 범위. 특정 생성 모델과 최종 차량의 동일성은 근거가 있을 때만 연결한다.

다음 연결: 기간 숫자의 한계를 짚은 뒤 여섯 게임에 공통된 도구 역할과 인간의 판단으로 정리한다.

### 08. 어디까지 왔을까

Unity와 Godot 같은 게임 엔진에서 돌아가는 작품도 있고, Three.js와 Phaser를 이용해 브라우저에서 실행하는 작품도 있었습니다. 게임을 실행하는 기반과, 그 게임을 만드는 데 도움을 준 AI는 서로 다른 역할을 맡고 있었죠.

AI가 쓰인 곳도 코드에만 머물지 않습니다. 입체 모델과 그림, 애니메이션 작업, 효과음과 음악까지 연결됩니다. 어떤 모델을 썼는지와 함께, 무엇을 생성했고 사람이 무엇을 골라서 고쳤는지를 보면 결과가 더 잘 보입니다.

오늘 내용은 이천이십육 년 시월 십팔 일에 확인한 공개 자료 기준입니다. 여섯 게임의 링크와 제작 기록은 설명란에 정리해 둘게요. 여러분은 어떤 게임을 직접 해 보고 싶으신가요?

화면 구성: 여섯 게임의 서로 다른 결과를 순서대로 회고. 실행 기반과 제작 AI를 두 역할로 정리하며 새 게임이나 확인되지 않은 AI를 추가하지 않는다.

다음 연결: 게임 링크 안내와 참여 질문 뒤 기존 회원 엔딩으로 이어진다.

- [ElevenLabs 효과음 생성](https://elevenlabs.io/sound-effects): 글로 원하는 효과음을 설명해 생성하는 기능. 음원 사용 조건은 실제 확보 단계에서 별도 확인.
- [Stability AI Stable Audio](https://stability.ai/stable-audio): 스타일·분위기 설명을 통한 음악 생성 기능. 최신 제품 버전을 Nightshoal 사용 버전으로 대입하지 않음.

- [Meshy 공식 제품 소개](https://www.meshy.ai/): 문장·이미지 기반 3D 모델 생성. 실제 게임의 메시/주행 동작까지 자동 완성했다고 주장하지 않음.
- [Sandscape 공식 소개](https://sandscape.app/): 요청·시각 편집·코드 수정·공유를 제공하는 브라우저 게임 제작 플랫폼. 내부 엔진은 확인되지 않음.
- [ElevenLabs 음악 생성](https://elevenlabs.io/music): 스타일·장르 등에 따른 음악 생성 기능. Rally의 정확한 사용 모델 버전은 미공개.
