# 코인 줍던 모자로 공룡까지? — 쇼츠 제작 구성

추천 이유: 익숙한 행동 하나가 보상 획득에서 캐릭터 캡처까지 확장되는 놀라움을, 실제 장면과 작동하는 같은 Unity 무대로 확인할 수 있다. 반응속도·학습효과의 미측정 수치를 만들지 않는다.

한 가지 주장: 캡처에 들어가는 익숙한 모자 던지기를 재사용한다. 캡처 뒤 이동·공격까지 같은 버튼이라는 주장은 하지 않는다.

## 전체 내레이션

코인이 나오던 모자로, 이번에는 공룡을 조종합니다.

슈퍼 마리오 오디세이의 시작점은 모자 던지기예요.

먼저 주변에 모자를 던지면 코인이 튀어나오죠. 이렇게 세계가 반응하는 걸 익힙니다.

그다음 같은 행동을 멍멍이에게 써 보면, 이번엔 그 몸을 조종하게 되죠.

이렇게 다른 대상의 몸과 능력을 빌리는 기능을 캡처라고 합니다.

우리 시연에서도 버튼과 던지기는 그대로예요.

맞는 대상만 바꾸면, 보상을 얻던 행동이 새 능력을 여는 행동으로 확장됩니다.

모자 던지기를 처음부터 다시 배울 필요가 없죠.

물론 공룡이 된 뒤의 이동과 공격은 따로 익힙니다.

오디세이는 새로운 능력을 소개할 때도, 이미 손에 익은 행동에서 출발하는 거예요.

## 연결되는 화면

1. 실제 T-Rex 캡처로 결말을 먼저 보여 준다. 모자 던지기는 원래 어떤 행동이었는지 다음 장면이 이어받는다.
2. Unity 무대에서 익숙한 던지기를 먼저 보인다. 보상 반응과 진행 화살표는 실제 충돌 쿼리의 실행값을 따른다.
3. 실제 모자의 나라에서 모자를 던진 뒤 코인이 나오는 반응을 확인한다. 정확한 개수나 보이지 않는 획득 수치를 주장하지 않는다.
4. 실제 멍멍이 캡처로 같은 행동의 새 결과를 보여 준 직후 정식 용어 ‘캡처(Capture)’를 붙인다.
5. 같은 Unity 무대·입력·투척 궤적으로 돌아와 대상만 바꾼다. 충돌 쿼리가 보상 획득과 조종권 이전을 실행하고, 같은 이동 입력이 새 조종 대상에게 전달된다. 보상 0→1 등 수치는 우리 구현의 실행값에만 쓴다.
6. 공룡의 Dash/Attack 안내와 실제 이동·파괴로 돌아온다. 이후 이동·공격은 따로 익힌다는 한계를 설명한다.
7. 같은 위치의 짧은 Unity A/B로 익숙한 행동에 새 쓰임을 연결한 구조를 정리한 뒤, 실제 공룡 장면과 오디세이의 선택으로 닫는다.

말과 화면은 같은 시간축에서 진행하며 장면마다 무음 관찰 시간을 넣지 않는다. 고양이는 반전·원리 지시·마무리의 필요한 순간만 오른쪽 아래 크게 등장한다. 출처 띠는 만들지 않고, 필수 표시와 링크는 두 언어 설명의 맨 아래에 둔다.

실측 발화·편집 프레임은 production-plan.json과 ../production/visual-timing.json에 연결한다. 현재 편집은 40.283초·2417프레임이다. 1080×1920/60fps 완성본·clean·KO/EN SRT를 로컬로 전달한다. 사용자 최종 검수 전 업로드하지 않는다.
