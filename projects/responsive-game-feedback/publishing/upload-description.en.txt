What should a game communicate when a button press cannot carry out the requested action? This lesson separates acknowledging input from explaining refusal, awaiting confirmation, and completing an action.

We look at the in-world controls in Aperture Desk Job and object highlighting in Half-Life: Alyx, then compare six original tests: a locked door, blocked construction, menu confirmation, cutscene skipping, a pending operation, and context-specific responses. Actual keyboard events and state logs verify the technical differences. The save example is explicitly a simulated delayed operation; human usability is not inferred from automation.
