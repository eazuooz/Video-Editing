# 원버튼 게임 디자인 — 편집 설계

질문: 버튼 하나만으로 플레이어에게 어떤 판단을 만들어 줄 수 있을까?
결론: 버튼 수보다 ‘무엇을 보고, 언제 누르고, 결과를 어떻게 읽는가’를 설계한다.

## 7개 독립 씬 / 본문 임시 240초

| 씬 | 주제 | 실제 게임 슬롯 | 자체 2.5D 설명 | 합계 |
| --- | --- | ---: | ---: | ---: |
| 01 | 버튼은 하나, 판단은 여러 개 | 14초 | 10초 | 24초 |
| 02 | 연타 — 얼마나 빠르게 누를까 | 19초 | 13초 | 32초 |
| 03 | 타이밍 — 지금 누르면 맞을까 | 26초 | 16초 | 42초 |
| 04 | 반응 — 신호가 나오면 눌러라 | 23초 | 15초 | 38초 |
| 05 | 누르기와 떼기 — 무엇을 받아들일까 | 26초 | 16초 | 42초 |
| 06 | 입력이 단순할수록, 결과는 선명하게 | 21초 | 15초 | 36초 |
| 07 | 버튼보다 먼저, 플레이어의 판단을 설계하자 | 15초 | 11초 | 26초 |
| 합계 | 본문 | 144초 (60%) | 96초 (40%) | 240초 |

이 수치는 기획값이지 현재 완성 영상의 비율이 아니다. 실제 게임 슬롯은 아직 자료 미확보.
TTS 실측 후 바꾸며 양 언어 자막·원음·BGM·씬 타이밍을 동시에 재계산한다.
짧은 자료를 반복/감속해 슬롯을 채우지 않는다. 추가 관련 시도와 결과 컷을 확보한다.
챕터 앞 실제 예시 → 동일 개념 자체 설명을 기본으로, 양쪽 모두 나레이션이 이어진다.
로고 인트로는 별도 확정. 10초 회원 감사 엔딩은 본문 비율에서 제외한다.

## 디자인
흰 배경 + 공유 연구 발표 테마. 입체 버튼, 투영된 발판, 이동 블록, 신호, 달걀/폭탄으로
입력과 판단을 연결한다. 단순 도식의 수치(반응 250ms 등)는 설명용 연출이며 실측/기록이 아니다.
긴 문장을 슬라이드에 나열하지 않는다. 24초 디자인 샘플은 네 방식 각각 6초다.
전체 임시 씬은 각 실제 영상 슬롯을 ‘확보 중’으로 명확히 표시한다.

## 승인 상태
- 대본: review.ko.md v1 사용자 검토 대기
- TTS: 대본 승인 후 짧은 균형형 샘플 → 승인 후 전체
- BGM: Discovery / Wanderlust / 없음 중 응답 대기
- 게임 출처: 후보만 기록, 원본 동작·버전·컷·재사용 조건 확인 대기
- 회원 엔딩: 원본 프로필·이름·뱃지 포함 이미지 요청 중
- 최종: 아직 제작 완료 아님
