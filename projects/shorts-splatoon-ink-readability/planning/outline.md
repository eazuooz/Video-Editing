# 스플래툰 2 — 잉크의 명암과 반짝임

닌텐도 개발자의 전체 설명과 실제 FHD 게임 화면을 확인해 KO/EN 대본을 확정했습니다. 음성·정확한 컷 타이밍·Unity 출력 검수는 아직 하지 않았습니다.

선택 제목: **반짝이는 잉크 때문에 적을 놓친다? | 스플래툰 2**

실제 게임 예시는 **Splatoon 3**의 광택과 캐릭터 잠수입니다. **Splatoon 2 개발 과정**은 닌텐도의 설명이 근거이며, 실패 조건 비교는 자체 Unity 모형으로 표시합니다. 상용 게임의 내부 셰이더 수식·수치나 현재 3편의 구현은 추정하지 않습니다.

## 확정 대본

스플래툰에서는 반짝이는 잉크 속으로 캐릭터가 숨어듭니다. 그런데 스플래툰 2 개발 중에는, 반짝임을 세게 하자 적이 잠기는 흔적이 잘 안 보였습니다. 잉크의 빛을 어떻게 조절해야 했을까요?

출발점은 전작의 잉크였습니다. 너무 번쩍이거나 납작해 보이는 곳이 있었죠. 그래서 2편에는 빛과 재질의 반응을 물리 원리에 맞춰 계산하는, 물리 기반 셰이딩을 도입했습니다.

그런데 울퉁불퉁한 잉크에 생긴 어두운 부분이, 우리 팀과 적 팀의 색 경계를 흐렸습니다.

이번엔 명암을 없애 봤습니다. 색은 구분하기 쉬워졌지만, 입체 지형에서 어디가 벽이고 바닥인지 읽기 어려워졌죠.

또 반사된 빛이 만드는 밝은 광택, 정반사를 강하게 했습니다. 그러자 적이 오징어로 변해 잉크에 잠길 때, 튀는 흔적이 잘 안 보였습니다.

그래서 잉크에서는 세 가지를 함께 읽을 수 있어야 했습니다. 두 팀의 색 경계, 벽과 바닥의 굴곡, 적이 잠기는 흔적입니다. 이 정보가 묻히지 않게 명암과 광택을 조정한 겁니다.

## 화면과 구현

1. 기존 독립 FHD 녹화 `splatoon-charger.mp4`의 로컬 66.0–68.2초(광택·바닥·벽), 70.0–72.8초(잠수·재등장) 합계 5초를 최소 필요 컷으로 선택했습니다. 원속도·정확한 경계·자막 맞춤은 실제 음성 후 확인합니다.
2. 도입 관찰 다음 “그런데 스플래툰 2 개발 중에는”에서 자체 Unity 장면으로 전환합니다. 3편 게임 화면을 2편의 실패한 시제품처럼 보여 주지 않습니다.
3. 같은 바닥·벽·두 색·카메라·조명·잠수 동작에서 명암 기여 또는 정반사 강도 하나만 바꿉니다. 숫자는 자체 모형의 파라미터입니다.
4. 자체 shader/controller/builder와 .meta를 작성했습니다. Unity 6000.6 실제 어셈블리로 C# CPU 컴파일은 오류·경고 없이 통과했습니다. 셰이더는 PC 품질 설정의 URP에 맞췄으며 전역 설정은 바꾸지 않았습니다. Unity Editor/빌더를 실행하지 않아 저장된 .unity, prefab, material, mesh 또는 렌더 결과는 아직 없습니다.
5. 끝에는 같은 Unity 장면의 색 경계·지형 굴곡·잠수 흔적을 함께 가리킵니다. 게임 도입 컷을 반복하지 않습니다.

## 근거와 권리 기록

- [Nintendo 개발자 설명](https://www.nintendo.co.jp/jobs/keyword/51.html)의 전체 교육 내용과 비교 이미지 3개를 읽었습니다. 이미지 자체는 연구용입니다.
- [Nintendo 가이드라인](https://www.nintendo.co.jp/networkservice_guideline/en/index.html)은 게임 IP 조건이며, 별도 녹화자의 권리를 대신하지 않습니다. Karmakazi의 명시적 재사용 허가는 확인되지 않았습니다. 부모 작업에서 짧은 필요 인용, 자체 해설·표식, 원본 오디오 제외, 설명란 출처를 갖춘 편집 근거로 선택했습니다. 허가를 받았거나 법적 확실성이 있다고 기록하지 않았습니다.
- 원본은 1920×1080/60fps이며 기존 파일을 그대로 참조합니다. 새 연구 이미지·검수 샘플은 C:에 보관합니다.
- 공식 2편 트레일러 후보는 HTTP403 또는 FHD 미확보였습니다. 공식 3편 직접 MP4 네 개도 실제 규격이 FHD 미만이라 제외했습니다.
- 초기에는 Overwatch 실행으로 GPU/TTS/렌더·Unity Editor를 보류했습니다. 이후 부모 작업이 게임 종료를 확인했고, 이번에는 CPU C# 검사만 수행했습니다. 실제 Editor·장면 생성·렌더는 부모 작업이 순차 진행합니다.
- 별도 요청인 바닥·벽 잉크 부착 편은 이 편과 합치지 않습니다.
