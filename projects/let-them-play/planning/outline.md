# v4 기획 — 게임의 첫 화면은 어떻게 설계할까?

## 영상의 정체성

게임 디자인 해설. 플레이어에게 무엇을 먼저 보이고, 어떤 행동을 유도하고, 어떤 결과를 남길지 다룬다.
코딩 튜토리얼·새 게임 기능 구현·엔진 시뮬레이션 제작 과정은 제외한다.
‘첫 화면’은 첫 플레이 가능 장면이며 이후 도입부로 이어지는 경험까지 연결한다.

비중: 야숨 관찰156초 + 디자인 해설156초 + 설계 비교156초 = 468초 가안.
8씬 각각19.5초씩 세 구간. 마지막 구간의 application 키는 기존 타이밍 호환용 식별자일 뿐, 화면/대본에는 ‘설계 비교’로 표시한다.

| 장 | 설계 질문 | 비교할 변수 |
|---|---|---|
| 1. 첫 화면은 무엇을 약속해야 할까? | 처음 보여줄 것은, 해보고 싶은 일 | 정보를 제시하는 순서 |
| 2. 내가 누구고, 어디로 가야 하지? | 낯선 세계 안에, 분명한 첫 행동 | 주인공과 첫 목표의 화면상 관계 |
| 3. 카메라는 무엇을 먼저 보게 할까? | 많이 보여주기보다, 먼저 볼 것을 정하기 | 강조의 우선순위 |
| 4. 처음에는 무슨 행동을 시킬까? | 처음 허용한 행동이 게임의 성격을 말한다 | 처음 요구하는 행동의 수와 순서 |
| 5. 눌렀다는 사실보다, 무엇이 달라졌는가 | 행동과 결과를 한 경험으로 연결하기 | 결과가 보이는 위치 |
| 6. 첫 실패 뒤에는 무엇을 알게 될까? | 실패의 원인과 다시 해볼 길을 남기기 | 위험 원인의 가시성 |
| 7. 설명은 언제 들어와야 할까? | 지금 필요한 정보와 나중의 정보를 나누기 | 같은 정보를 전달하는 시점 |
| 8. 첫 화면은 다음 장면을 궁금하게 해야 한다 | 무엇을 보고, 무엇을 하고, 왜 계속할까? | 첫 행동 이후의 연결 |

## 설명과 비교의 역할

두번째⅓: 관찰 사례가 던지는 디자인 원리를 설명한다.
세번째⅓: 같은 상황에서 구도·강조·정보 순서 중 해당 변수를 바꿨을 때 읽히는 차이를 설명한다.
A/B를 무조건 나쁨/좋음으로 판정하지 않으며 비교 그림은 출시 게임의 실제 다른 버전이 아니다.
2D/2.5D는 원리를 표현하는 수단이지 영상의 주제가 아니다. 주인공/대상/출구 등 관계를 읽히게 한다.

설계 비교 8개 구간은 같은 공간의 배치·강조·정보 순서를 비교하는 2.5D 애니메이션으로 제작했다.
원본 야숨 영상·TTS·음성 동기 SRT·BGM은 아직 없다. 비교 구간만 모은 156초 무음 검토본과 본편468초 초안을 구분한다.
기존 렌더는 보존하며 v4 완료본으로 표시하지 않는다. 기존 흰 연구 발표형 스타일 및 연속 내레이션/연속 BGM 기준 유지.
