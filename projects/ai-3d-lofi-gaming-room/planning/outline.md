# AI로 만드는 3D LOFI 게이밍룸 제작 구성

기존 2D 방을 **웹에서 접속해 직접 눌러 사용하는 작은 3D 게이밍룸**으로 확장한다. 최종 실행 환경은 Unity WebGL 2이며, 별도 실행 프로그램 설치 없이 브라우저에서 플레이하는 것을 목표로 한다. Spirit City: Lofi Sessions는 조용한 방에서 음악을 들으며 쉬고 집중하는 경험을 참고한다. 방·캐릭터·소품은 자체 디자인으로 만들며, 같은 방이 영상 처음부터 끝까지 완성되어 가는 흐름을 유지한다.

현재는 Tripo H3.1 캐릭터·헤드폰, 실제 걷기·대기 모션을 적용한 첫 Unity 샘플과 36초 FHD60 검수 영상, Windows 실행 파일까지 준비됐다. 방은 기본 구조 단계이며 전체 제작 영상·앉기·독서·메모 UI는 아직 제작 중이다. 사용자 요청으로 WebGL 모듈 설치와 웹 빌드는 뒤로 미뤘다. 다음 영상 구성에는 실제 실행한 도구와 후보를 구분하는 [MCP·도구 실행표](mcp-tools.md)를 적용한다. 상세 상태와 실행 증거는 [제작 계획](production-plan.json), [첫 샘플 기록](../production/unity-sample-delivery.json)에 모은다. 저장공간은 각 큰 작업 전에 다시 확인한다.

## 게임에서 할 수 있는 일

| 클릭할 대상 | 이어지는 행동과 변화 |
|---|---|
| PC와 책상 | 걸어가기 → 의자 앞 정렬 → 앉기 → 게임 또는 공부 → 일어나기 |
| 책 | 책 앞으로 이동 → 꺼내기 → 펼쳐 읽기 → 덮기 → 복귀 |
| 창문과 날씨 | 낮·밤, 맑음·비 선택. 창밖의 색과 빗소리, 실내 조명이 함께 바뀐다 |
| 화면 안 라디오 | 음악 재생·정지·다음 곡, 음악과 빗소리 음량을 따로 조절한다 |
| 메모와 타이머 | 간단한 메모를 저장하고 집중·휴식 시간을 설정한다 |
| 고양이 | 조용히 쉬는 동반자. 확보된 자연스러운 기본 모션을 사용한다 |

책상·의자·캐릭터를 같은 실제 크기 기준으로 맞춘다. 앉아 있을 때 무릎이 책상을 통과하거나, 이동 거리와 발걸음이 어긋나지 않도록 대표 장면에서 먼저 검증한다. 전체 방 시점과 책상 근접 시점을 준비해 결과와 제작 과정을 모두 읽을 수 있게 한다.

## 도구 후보 10개와 각 결과물

| 도구 | 방 안에서 보여 줄 활용 |
|---|---|
| ChatGPT 이미지 생성 | 방 콘셉트, 캐릭터와 소품 참고 이미지. 현재 방 콘셉트 1장 생성 |
| Meshy | 참고 이미지에서 캐릭터·소품 생성. 실제 생성 결과를 회전시켜 확인 |
| Tripo | 같은 소품의 대안 생성, 작은 책상 소품 제작 |
| ComfyUI + Hunyuan3D | 이미지→3D 노드 흐름과 비교 후보. 클라우드/로컬 모델 경로를 구분 |
| Blockbench | 정확한 크기의 책상·모니터와 저폴리곤 소품, UV·색상 보정 |
| Material Maker | 책상 나무와 의자 직물의 반복 가능한 PBR 재질 |
| Mixamo | 휴머노이드 자동 리깅, 제공되는 실제 걷기·대기·앉기 클립 |
| DeepMotion Animate 3D | 권리를 확보한 전신 영상에서 기지개 같은 동작 추출 |
| Codex | 클릭 동작·날씨·음악·메모·타이머 구현과 오류 수정 |
| Unity 6 URP | 한 씬으로 통합, 조명·Animator·접촉 보정·게임 실행·Web 빌드 |

이 목록은 제작 후보이며 모든 도구 실행 완료를 뜻하지 않는다. 모델 생성 서비스는 같은 소품을 기준으로 형태·뒤쪽 면·텍스처·파일 크기·실제 비용을 비교한다. 잘 나온 결과와 수정한 결과, 실패한 결과를 구분한다. 도구의 무료 여부·내보내기·출력물 사용 조건은 실제 계정과 선택 모델을 확인한다.

## 영상 구성과 연결

| 순서 | 실제 보여 줄 화면 | 설명의 핵심과 다음 연결 |
|---|---|---|
| 1. 먼저 방을 써 본다 | 완성 게임에서 앉기·날씨·라디오를 조작 | “지난번 도트 방을, 이번에는 안에서 움직일 수 있는 3D 게이밍룸으로 확장합니다.” 실제 완성 후 촬영한다 |
| 2. 무엇을 3D로 만들까 | 이전 2D 방과 새 방의 배치·행동 도식 | 그림 한 장에는 보이지 않는 뒷면과 부피가 필요하다 → 같은 디자인의 참고 이미지 |
| 3. 디자인을 고정한다 | 방/캐릭터/소품 시트와 실제 프롬프트 | 모델마다 생김새가 달라지지 않게 입력을 고정 → 같은 소품 3D 생성 |
| 4. 이미지가 입체가 된다 | 같은 헤드폰의 Meshy·Tripo·Hunyuan 결과와 회전 | 앞·뒤·접합부와 실제 mesh를 비교해 채택 → 정확한 가구 크기와 보정 |
| 5. 앉을 수 있는 가구를 만든다 | Blockbench의 책상·의자 치수, Unity 인체 기준 | 모양이 좋아도 의자와 몸 크기가 다르면 앉을 수 없다 → 재질·동작을 같은 규모에 적용 |
| 6. 그림과 표면의 차이 | Material Maker 목재/직물과 Unity 조명 아래 적용 | 색 그림과 빛 반응을 구분. PBR은 빛에 반응하는 표면 설정 → 움직일 캐릭터 |
| 7. 자연스럽게 걷고 앉는다 | Mixamo 리깅·실제 클립, root motion과 접촉 비교 | 뼈대와 리깅의 쉬운 의미를 설명하고 실제 clip으로 연결 → 없는 동작 확보 |
| 8. 영상에서 동작을 얻는다 | 허가된 전신 입력 영상·DeepMotion 추출·적용 결과 | 영상 기반 추출과 기존 motion library의 차이 → 방 안에서 행동을 이어 주는 코드 |
| 9. 눌렀을 때 반응하게 만든다 | 클릭 → 목적지 → 정렬 → 동작 상태도와 Unity 실행 | 모양·동작·행동 규칙을 연결. 손/책상 접촉과 이동거리 확인 → 분위기·생활 기능 |
| 10. 오래 켜 둘 방으로 만든다 | 음악·비·밤 조명·메모·집중 타이머 조작 | 감상용 영상에서 실제 조작 가능한 공간으로 발전 → Web 실행 검증 |
| 11. 실제로 플레이한다 | Web 빌드 결과와 접속·저장·오디오 동작 | 성능/지원 조건과 실제 성공·실패 결과만 설명. 공개 URL은 배포 완료 후 기재 |
| 12. 약 10초 정리 | 같은 방에서 이미지→모델·재질→동작→게임 관계 재확인 | “디자인을 맞추고, 모델과 움직임을 다듬고, 행동 규칙으로 연결했습니다.” 이후 기존 멤버 엔딩 |

## 시연과 설명 기준

각 도구는 **입력과 프롬프트 → 실제 출력 → 보정 → 방 안에서 쓰는 장면**을 연결한다. 결과를 실제로 확인한 뒤 최종 내레이션을 확정한다. 완성하지 않은 모델이나 기능을 성공한 것처럼 소개하지 않는다. 도구 이름만 읽는 소개 슬라이드는 짧게 하고, 설명은 현재 화면의 물체와 변화에 붙인다.

부자연스러운 관절 회전으로 걷기·앉기를 흉내 내지 않는다. 검수한 기존 native clip과 실제 추출 동작을 사용하고, 손·책·키보드의 접촉과 전환을 보정한다. 흰 글자·노란 핵심 제목의 얌얌코딩 설명 규칙, 개론·마지막 정리·연결된 챕터, 1080p60 출력과 한영 자막을 유지한다.

배경음악은 기존 2D 게임에서 확인한 CC0 기록을 다시 대조해 채택한다. 참고 게임의 음악이 방송에 허용된다는 안내를 우리 게임에 재배포할 권리로 해석하지 않는다. 실제 사용 도구·자산·음악 출처는 설명란 맨 아래에 정리한다.

## 웹 실행 기준

최종 납품은 브라우저에서 실행하는 Unity WebGL 게임이다. PC Chrome·Edge부터 검증하며 마우스·터치가 가능한 반응형 UI를 설계한다. 모바일의 실제 지원과 성능은 별도 기기 검증 결과로 기록한다. 에디터에서 잘 실행되는 것만으로 웹 완성을 표시하지 않는다.

처음에는 방과 기본 동작부터 불러오고 음악은 선택한 곡을 순서대로 로드한다. 시작 버튼을 누른 뒤 음악을 재생하며 화면 안에서 음량·음소거·다음 곡을 조절한다. 메모와 설정은 해당 브라우저에 저장하며 계정 간 동기화를 약속하지 않는다. 기본 구도·재질·부드러운 조명으로 분위기를 유지하고, 큰 텍스처·모델 밀도·실시간 그림자 비용을 줄인다.

로딩 진행·실패 재시도·전체 화면·해상도/품질 조절을 준비한다. 실제 HTTPS 주소에서 압축·WASM 로딩, 오디오 시작, 메모 유지, 새로고침, 탭 복귀를 확인한다. 접속 링크는 배포 성공 후에만 최종 영상 설명란에 넣는다.
