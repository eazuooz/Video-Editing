# 벅샷 룰렛 분석·재구현 과정 촬영

실제로 수행한 작업만 편집한다. 처음부터 완성된 결과를 만든 것처럼 오류·실패·수정 횟수를 숨기거나, 기록되지 않은 백그라운드 작업을 촬영 영상으로 표시하지 않는다. 실제 화면 재시연은 그 사실을 편집 기록에 남긴다.

| 단계 | 실제로 확인할 것 | 촬영할 화면 | 설명의 연결 |
|---|---|---|---|
| 원작 관찰 | 탄 공개 → 조준 선택 → 결과 → 다음 턴 | 원작 게임, 필요한 동작 전체 | 보기에는 간단한 선택인데 어떤 규칙이 숨어 있을까 |
| 설치 구조 | 실행 파일과 패키지, 실제 엔진 버전 | 파일 목록·REA 실제 출력 | 규칙을 찾으려면 먼저 파일 구조를 구분해야 한다 |
| 탄과 턴 | 탄 종류·순서, 자신/상대 조준 결과 | 확인한 분석 증거·짧은 상태도 | 겉으로 같은 발사라도 다음 턴이 달라진다 |
| 아이템·판단 | 상태 변경·정보 획득·상대 선택 | 실제 근거와 독립 테스트 | 확률만으로 게임을 설명할 수 없는 이유 |
| 새 시각 표현 | 독립 모델·재질·조명·인터랙션 | Blender/Godot 작업 화면 | 확인한 규칙에 다른 외형을 입힌다 |
| 검증 | 같은 입력·조건에서 기대 결과 확인 | 원작 관찰과 자체 구현을 구분한 비교 | 비슷해 보이는 것과 규칙이 맞는 것은 다르다 |
| 결론 | 실제로 재현한 범위·실패·남은 차이 | 실제 플레이 가능한 결과 | 처음 질문에 확인한 사실로 답한다 |

2026-10-29 원작 직접 플레이를 OBS로 두 차례 촬영했다. `captures/recordings/buckshot-process-2026-10-29_09-15-02.mkv`와 `buckshot-process-2026-10-29_09-22-48.mkv`는 1920×1080/60fps이며 게임 창과 해당 게임 소리만 담았다. 마이크와 전역 데스크톱 소리, 외부 성능 오버레이는 제외했다. 길게 멈춘 작업 대기 구간은 편집에 사용하지 않고 실제 행동과 결과가 이어지는 구간을 `original-footage-audit.json`에 기록해 선택한다.

촬영 후 원작을 종료하고 기존 사용자 저장 파일 네 개의 SHA256이 모두 촬영 전과 같음을 확인했다. 게임은 별도의 작업용 사용자 데이터 경로로 실행했다. 자체 구현 FHD 시연은 `captures/prototype-demo-fhd.avi`에 별도로 저장했다. 실제 분석 결과 화면을 다시 보여주는 부분은 현재 증거 재시연이며 과거 작업 순간의 녹화로 꾸미지 않는다. 코드·출력 글씨는 FHD에서 읽히는 크기로 확대하고 개인정보·키·Steam 계정 식별자는 촬영에서 제외한다.
